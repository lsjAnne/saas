## 1. 文档目的
本文档定义项目的总体系统架构、系统边界、分层原则、部署拓扑和交付基线，用于统一产品、架构、研发、测试和运维对平台的认知，作为后续研发实施、联调验收和商用交付的正式依据。

## 2. 产品与交付定位
### 2.1 平台定位
- 本项目定位为一套可按 `SaaS` 模式和私有化模式交付的多租户电商经营平台。
- 平台目标不是单点工具，而是围绕 `SaaS 平台底座 + OMS + SRM + ERP 基础能力 + CRM + WMS/TMS 扩展 + BI` 形成完整经营系统。
- 模型能力属于增强层，用于提高内容生成、回复辅助、脚本生成和经营分析效率，不替代主业务系统。

### 2.2 交付模式
| 交付模式 | 说明 | 适用场景 |
| --- | --- | --- |
| 标准 SaaS 版 | 平台统一托管，多租户共享应用与基础设施，通过租户、组织、权限、配额和审计隔离 | 中小商家、多店铺团队、平台型服务商 |
| 私有化部署版 | 单客户独立环境，数据、配置、监控和备份隔离，可按客户网络与合规要求适配 | 集团客户、强合规行业、独立网络环境 |

### 2.3 系统边界
| 系统域 | 本项目职责 | 边界说明 |
| --- | --- | --- |
| SaaS 平台底座 | 租户、组织、权限、订阅、计费、配额、停复服、退租、审计 | 不替代客户内部 IAM 或独立财务主系统 |
| OMS | 订单同步、标准化、审单、履约编排、异常处理 | 不承担深度仓储执行和运输调度细节 |
| SRM | 供应商准入、主备管理、协同、风险标记 | 不替代大型采购招投标系统 |
| ERP 基础能力 | 库存、补货、采购、账单、结算、利润核算基础 | 当前聚焦经营型 ERP 基础，不覆盖全财务总账 |
| CRM | 会话、工单、售后、会员、标签、复购运营 | 不替代全渠道呼叫中心或大型客服平台 |
| WMS/TMS | 纳入仓储执行和物流跟踪统一架构边界，定义标准扩展接口与对象模型 | 当前按扩展域设计，不伪装成已完整落地子系统 |
| BI | 指标口径、数据分层、经营看板、分析接口 | 不直接改写主业务事实数据 |
| 模型辅助层 | 文案、脚本、建议、解释、知识检索增强 | 不跳过业务规则直接做高风险落库 |

## 3. 总体架构目标
- 支持多租户、多组织、多店铺、多渠道经营。
- 支持订单、商品、供应商、库存、客服、财务、营销、直播、运营分析的主链路闭环。
- 支持平台治理能力，包括订阅计费、配额控制、日志审计、支持介入、退租清理。
- 支持标准 SaaS 与私有化两种交付形态。
- 支持开放平台、插件和第三方系统集成。
- 保证关键链路稳定、可追踪、可审计、可扩展。

## 4. 系统上下文架构
### 4.1 外部系统上下文
| 外部系统 | 对接目的 | 数据方向 | 本平台责任 |
| --- | --- | --- | --- |
| 电商平台 | 店铺授权、订单同步、商品发布、物流回传、会话接入 | 双向 | 提供连接器、适配器、幂等控制和异常补偿 |
| 货源/供应商平台 | 候选商品、供应商档案、价格库存读取 | 读多写少 | 统一货源抽象、映射管理和风险标记 |
| 物流平台 | 运单状态、轨迹、签收、异常回传 | 双向 | 提供履约回传、轨迹更新和异常收口 |
| 消息平台 | 短信、邮件、站内信、飞书通知 | 出向为主 | 统一通知模板、发送任务和重试机制 |
| 支付/财税平台 | 订阅计费、发票、结算扩展 | 双向 | 定义账单、支付、发票对象模型和接口边界 |
| BI / 数仓环境 | 指标加工、主题分析、看板服务 | 出向为主 | 输出经营事实、指标口径和快照基线 |
| 第三方 ERP/WMS/CRM | 客户已有系统集成 | 双向 | 通过开放平台和连接器做标准集成，不侵入第三方实现 |

### 4.2 平台内部上下文
| 层级 | 组成 | 核心职责 |
| --- | --- | --- |
| 业务入口层 | Web 前端、开放接口、回调入口、平台后台 | 承载用户操作、第三方集成和管理入口 |
| 应用编排层 | 订单编排、库存编排、客服编排、审批编排、通知编排、租户生命周期编排 | 负责跨模块流程和事务边界 |
| 领域服务层 | 店铺、商品、供应商、订单、履约、客服、会员、财务、审批、通知、订阅 | 负责领域规则和核心业务状态流转 |
| 集成适配层 | 电商平台连接器、货源连接器、物流连接器、消息连接器、开放平台适配器 | 负责与外部系统协议、鉴权、重试和映射 |
| 治理支撑层 | 权限、租户上下文、审计、风控、幂等、支持会话 | 负责横切治理能力 |
| 数据与基础设施层 | H2/PostgreSQL、Redis、对象存储、消息队列、日志、指标快照、检索 | 负责数据存储、缓存、异步和观测支撑 |

### 5.2 技术分层
平台采用 `接口层 -> 应用层 -> 领域层 -> 仓储抽象层 -> 基础设施层` 的标准分层：

| 分层 | 职责 | 典型对象 |
| --- | --- | --- |
| 接口层 | HTTP API、平台后台接口、开放接口、回调入口、参数校验、统一响应 | `Controller`、`Request/Response DTO` |
| 应用层 | 跨模块编排、事务边界、任务发起、权限入口、流程控制 | `ApplicationService` |
| 领域层 | 领域模型、领域规则、状态流转、业务不变量 | `Model`、`Domain Service` |
| 仓储抽象层 | 领域仓储接口、查询边界、聚合持久化抽象 | `Repository` |
| 基础设施层 | JDBC、缓存、消息、对象存储、连接器、审计落库、幂等 | `JdbcRepository`、`InMemoryRepository`、`Connector` |

## 6. 架构形态与交付基线
### 6.1 当前交付架构形态
本项目采用：

`模块化单体 + 明确领域边界 + 横切治理能力独立收口 + 外部集成连接器化`

该形态用于保证：
- 当前阶段能快速形成完整业务闭环。
- 代码结构和业务边界已经按持续扩展口径完成整理。
- 不把复杂度过早引入到多服务拆分和分布式治理中。

### 6.2 交付版演进原则
- 标准版与私有化版共用统一业务模型和接口模型。
- 交付时允许按部署形态拆出独立进程，但不改变领域边界。
- 所有扩展能力必须通过标准应用层、连接器层或开放平台接入，不允许绕过审计和租户隔离。

## 7. 关键业务链路
### 7.1 SaaS 生命周期链路
租户开通 -> 试用订阅 -> 套餐生效 -> 配额控制 -> 续费/升级/降级 -> 停服/恢复 -> 退租 -> 数据导出 -> 清理归档

### 7.2 OMS 主链路
店铺接入 -> 订单同步 -> 订单标准化 -> 审单 -> 履约编排 -> 物流回传 -> 异常处理 -> 经营看板沉淀

### 7.3 SRM / ERP 主链路
供应商准入 -> 商品与货源映射 -> 库存快照 -> 补货任务 -> 采购协同 -> 入库回写 -> 账单与结算归档

### 7.4 CRM 主链路
买家提问 -> 会话识别 -> 知识检索 -> 回复辅助 -> 转人工/发送 -> 售后工单 -> 标签回写 -> 复购运营

### 7.5 直播与内容链路
直播计划 -> 商品绑定 -> 脚本生成 -> 配额校验 -> 开播执行 -> 状态回调 -> 数据沉淀 -> 经营复盘

### 7.6 BI 主链路
业务事实沉淀 -> 指标快照 -> 主题聚合 -> 经营看板 -> 分析结论输出

## 8. 多租户、权限与治理架构
### 8.1 租户隔离原则
- 所有业务对象默认带 `tenant_id`。
- 组织协同对象带 `organization_id`。
- 店铺经营对象带 `store_id`。
- 平台侧访问与租户侧访问物理分层，不通过一个入口切换身份。

### 8.2 支持介入原则
- 平台支持人员进入租户业务详情必须依赖有效 `support session`。
- 支持会话必须有原因、审批、范围、有效期和审计记录。
- 支持介入期间所有查询、导出、关闭动作必须回写 `audit_log`。

### 8.3 审计原则
- 高风险操作必须记录 `actor_id`、`action_type`、`target_type`、`target_id`、`operation_result`、`trace_id`。
- 敏感字段默认脱敏展示。
- 日志、导出、清理、停复服、授权重置等能力必须全链路留痕。

## 9. 标准部署架构
### 9.1 交付组件
| 组件 | 作用 | 标准 SaaS 版 | 私有化版 |
| --- | --- | --- | --- |
| Web 前端 | 业务操作入口与平台后台入口 | 必选 | 必选 |
| API 主服务 | 主业务接口、平台接口、开放接口 | 必选 | 必选 |
| Job Worker | 定时任务、对账、清理、巡检 | 必选 | 必选 |
| Callback Worker | 外部回调消费、重试、补偿 | 必选 | 按集成场景启用 |
| AI Worker | 模型编排、异步生成、评测任务 | 按能力启用 | 按能力启用 |
| PostgreSQL | 主业务库 | 必选 | 必选 |
| Redis | 缓存、幂等、临时状态 | 必选 | 必选 |
| 对象存储 | 素材、导出文件、附件 | 按业务能力启用 | 按业务能力启用 |
| 消息队列 | 异步解耦、回调消费、削峰 | 按业务能力启用 | 按业务能力启用 |
| 观测栈 | 日志、指标、告警、追踪 | 必选 | 必选 |

### 9.2 部署约束
- 所有部署形态都必须保留租户隔离、审计留痕和配置安全注入能力。
- 私有化部署不改变业务边界，只改变环境边界和运维边界。
- 不允许将平台后台与租户业务前台混用一套无边界菜单和接口域。

## 10. 架构结论
本项目的正式交付架构基线为：

`多租户电商经营平台 + 模块化单体业务内核 + 标准应用分层 + 横切治理能力 + 连接器集成框架 + SaaS/私有化双交付模式`

该架构既能支撑当前版本形成可用软件，也可作为正式开发计划、详细设计和实施计划生成的上位依据。
