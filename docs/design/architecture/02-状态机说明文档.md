| --- | --- | --- | --- | --- | --- |
| 状态机说明文档 | 架构/状态设计 | v1.2 | 状态流转设计、接口联调、测试验收 | 产品、后端、前端、测试 | 已整理 |

## 1. 文档目的
定义系统核心业务对象的状态集合、状态流转规则、触发条件和约束。

## 2. 设计原则
- 状态字段必须简洁明确
- 不允许跨状态跳转失控
- 所有状态变更必须留痕
- 外部回调不得直接写最终状态，必须走状态机校验

## 3. 店铺授权状态
字段：Store.auth_status

状态：
- connected
- disconnected
- expired
- error

流转：
- disconnected -> connected
- connected -> expired
- connected -> error
- expired -> connected
- error -> connected

## 12. 直播计划状态
字段：LivePlan.plan_status

状态：
- draft
- ready
- scheduled
- running
- ended
- cancelled

流转：
- draft -> ready
- ready -> scheduled
- ready -> running
- scheduled -> running
- running -> ended
- draft -> cancelled
- ready -> cancelled
- scheduled -> cancelled

约束：
- `running` 仅表示当前计划存在进行中的 `live_session`
- 已 `ended` 或 `cancelled` 的计划不得重新进入 `running`

## 13. 直播会话状态
字段：LiveSession.session_status

状态：
- created
- running
- paused
- manual_takeover
- degraded
- failed
- ended

流转：
- created -> running
- running -> paused
- paused -> running
- running -> manual_takeover
- paused -> manual_takeover
- running -> degraded
- degraded -> running
- degraded -> manual_takeover
- running -> failed
- paused -> failed
- manual_takeover -> ended
- running -> ended
- paused -> ended

约束：
- `manual_takeover` 表示直播由人工场控或人工主播主导，系统只保留辅助能力
- `degraded` 表示自动化能力部分降级但会话仍保持直播进行
- `failed` 只能由风险事件、平台回调异常或启动失败触发

## 14. 直播并发排队状态
字段：LiveConcurrencyQueue.queue_status

状态：
- pending
- granted
- timeout
- cancelled

流转：
- pending -> granted
- pending -> timeout
- pending -> cancelled

约束：
- 同一 `live_plan_id` 在同一时刻只允许一个有效 `pending` 排队记录
- `granted` 后必须在约定时窗内消费开播资格，否则应重新进入 `pending` 或标记 `timeout`

## 15. 直播场景切换状态
字段：LiveSceneSwitchRecord.switch_status / rollback_status

状态：
- pending
- switching
- success
- failed
- rollback_success
- rollback_failed

流转：
- pending -> switching
- switching -> success
- switching -> failed
- failed -> rollback_success
- failed -> rollback_failed

约束：
- 场景切换失败后必须立即进入回退判定，不允许停留在未知状态
- 连续 `rollback_failed` 达到阈值时必须触发 `manual_takeover`

## 16. 直播人工接管状态
字段：LiveManualTakeoverRecord.takeover_status

状态：
- pending
- active
- released
- rejected

流转：
- pending -> active
- pending -> rejected
- active -> released

约束：
- 接管激活后，`live_session.session_status` 必须同步进入 `manual_takeover`
- 接管释放后，会话只能回到 `running` 或直接 `ended`，不得回到 `created`

## 17. 直播承诺审核状态
字段：LiveCommitmentAudit.audit_status

状态：
- auto_allowed
- pending_confirm
- approved
- rejected
- blocked

流转：
- auto_allowed -> approved
- pending_confirm -> approved
- pending_confirm -> rejected
- pending_confirm -> blocked

约束：
- `blocked` 表示命中禁止承诺，不得再走审批放行
- `approved` 后必须生成履约跟踪要求或明确标记无需履约跟踪

## 18. 直播互动处理状态
字段：LiveInteractionEvent.reply_status / transfer_status

状态：
- pending
- auto_replied
- transferred
- replied
- ignored

流转：
- pending -> auto_replied
- pending -> transferred
- transferred -> replied
- pending -> ignored

约束：
- 命中高风险问答时，不允许从 `pending` 直接流转到 `auto_replied`
- `transferred` 必须带目标处理人或处理角色

## 19. 状态机约束
- 订单状态与履约任务状态分开维护
- 商品草稿状态与正式商品状态分开维护
- 异常任务状态不可直接绕过 processing 进入 resolved
- 所有重试必须带重试次数
- 所有取消操作必须带原因
- 直播相关状态变更必须同时校验租户配额、账号占用和风控结果
- 直播人工接管、承诺审核、场景切换失败回退都必须具备审计留痕
- 外部直播平台回调只允许触发候选状态变更，不允许绕过内部状态机直接改终态

## 20. 审计要求
每一次状态变更必须记录：
- 对象类型
- 对象 ID
- 旧状态
- 新状态
- 触发来源
- 操作人或系统动作
- 时间
- trace_id
