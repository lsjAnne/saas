# 运维监控与告警方案

## 1. 文档目的
本文档定义系统运行中的监控指标、日志要求、告警等级、值班处置、备份恢复和巡检流程，作为商用 SaaS 版本的运维基线。

## 2. 监控分类
### 2.1 应用监控
- 服务存活
- CPU、内存、线程数
- 接口响应时间与错误率
- 数据源连接池、Redis 连接状态

### 2.2 业务监控
- 租户开通成功率
- 店铺接入成功率
- 订单同步成功率
- 履约成功率
- 异常任务新增量与积压量
- 审批处理时长
- 通知投递成功率
- 财务账单生成、对账、结算成功率
- 订阅到期、停复服、配额命中情况

### 2.3 经营看板监控
- `GET /api/dashboard/summary` 可用性
- `GET /api/dashboard/trends` 数据刷新延迟
- `GET /api/dashboard/risks` 风险项数量与等级变化
- `GET /api/dashboard/campaign-analysis` 营销转化波动
- `GET /api/dashboard/member-analysis` 会员活跃与复购波动

### 2.4 外部依赖监控
- PostgreSQL 可用性与慢查询
- Redis 可用性与内存占用
- 第三方平台接口成功率
- 模型服务成功率、耗时与超时率
- 对象存储与消息队列可用性

## 3. 日志要求
- 应用日志：请求入口、异常堆栈、关键状态流转
- 审计日志：租户、审批、通知、财务、支持会话、权限变更
- 任务日志：定时任务、通知重试、账单生成、巡检任务
- 回调日志：平台回调、开放平台回调、外部通知回执
- 发布日志：版本号、执行人、迁移版本、回滚动作

要求：
- 关键日志必须带 `traceId`
- 关键日志必须带 `tenant_id`
- 平台支持跨租户查询必须单独记录查询原因

## 4. 告警等级
### P0
- SaaS 平台底座不可用
- 订单同步中断
- 履约任务大面积失败
- 财务结算接口不可用
- 驾驶舱总览不可用

### P1
- 第三方平台接口持续失败
- 异常任务快速积压
- 审批、通知或导出持续失败
- 配额校验或订阅状态异常导致租户大面积受阻

### P2
- 个别模型生成失败率上升
- 个别功能响应变慢
- 会员分析、营销分析、趋势分析延迟升高

## 5. 看板风险项与运维告警映射
| 看板风险项 | 触发条件 | 告警级别 | 处置动作 |
| --- | --- | --- | --- |
| 高风险异常积压 | 异常中心未处理数量持续升高 | P1 | 分派值班人员，暂停高风险自动化动作 |
| 通知投递失败 | `failed` / `dead_letter` 快速增加 | P1 | 检查模板、渠道与重试队列 |
| 财务结算滞留 | 未结算账单超阈值 | P1 | 核查对账链路，必要时切人工复核 |
| 订阅能力异常 | 套餐能力或配额口径异常 | P1 | 检查订阅状态、配额刷新与缓存同步 |
| 营销效果骤降 | 转化率或使用率异常波动 | P2 | 排查活动配置与流量策略 |
| 看板接口不可用 | 任一看板接口持续 5xx | P0/P1 | 先恢复接口，再追溯聚合链路 |

## 6. 备份、恢复与巡检 SOP
### 6.1 备份 SOP
1. 每日备份 PostgreSQL 全量数据或按策略执行增量备份。
2. 对 Redis 核心业务键空间保留快照。
3. 备份应用配置、发布版本号和迁移版本。
4. 备份结果必须记录时间、大小、保存位置和校验结果。

### 6.2 恢复 SOP
1. 明确恢复范围和目标时间点。
2. 先下线高风险写入任务。
3. 恢复数据库，再恢复关键缓存。
4. 重启应用并执行健康检查。
5. 验证租户开通、订单同步、审批通知、财务账单、驾驶舱五条关键链路。

### 6.3 巡检 SOP
1. 检查数据库、Redis、应用进程和磁盘空间。
2. 检查迁移版本与部署版本是否一致。
3. 检查告警积压、死信任务、未结算账单和高风险异常数。
4. 检查看板接口是否可访问、数据是否更新。
5. 输出巡检结论与整改项。

## 8. 结论
运维方案不是上线后的补丁，而是商用版本的一部分。只要监控、告警、备份和恢复链路不完整，平台就不能视为具备稳定对外服务能力。
