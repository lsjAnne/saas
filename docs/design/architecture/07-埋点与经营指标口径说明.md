# 埋点与经营指标口径说明

| 文档名称 | 文档类型 | 当前版本 | 适用对象 | 主要读者 | 维护状态 |
| --- | --- | --- | --- | --- | --- |
| 埋点与经营指标口径说明 | 架构/指标口径 | v2.0 | 埋点设计、指标统一、报表验收、数仓建设 | 产品、前端、后端、数据、BI、测试、平台运营 | 已整理 |

## 1. 文档目的
本文档用于统一前端埋点、业务事件、经营指标和验收规则，确保首页看板、BI 报表、数仓事实表、运营分析和测试结果使用同一套统计口径。

## 2. 事件采集架构
### 2.1 事件链路
1. 前端页面行为、后端业务动作、平台回调和任务执行统一产出标准事件。
2. 标准事件进入埋点接收层或日志采集层，写入 `ODS` 原始事件表。
3. 数据团队按事件类型沉淀 `DWD` 明细事实表，再汇总形成 `DWS` 和 `ADS` 指标结果。
4. 指标展示层只消费统一口径的数据集，不绕过标准事件直接拼接前端口径。

### 2.2 事件标准字段
| 字段 | 说明 |
| --- | --- |
| `event_code` | 事件编码，系统内唯一 |
| `event_name` | 事件名称 |
| `event_time` | 事件发生时间 |
| `tenant_id` | 租户边界 |
| `organization_id` | 组织边界 |
| `store_id` | 店铺边界 |
| `actor_id` | 操作人或任务主体 |
| `source_module` | 来源模块，如 `oms`、`crm`、`billing` |
| `source_table` | 对应业务表 |
| `source_id` | 对应业务对象 ID |
| `trace_id` | 全链路追踪标识 |
| `result_code` | 结果标识，如 `success`、`failed`、`rejected` |

## 4. 核心经营指标口径
| 指标名称 | 口径定义 | 主要来源表 |
| --- | --- | --- |
| 今日订单数 | 当天成功同步进入系统的订单数量 | `order_main` |
| 今日销售额 | 当天订单总成交额，不扣除退款和平台费用 | `order_main` |
| 预计毛利 | 订单收入减去货源成本和基础履约成本后的粗略利润 | `order_main`, `finance_bill` |
| 待处理异常数 | 状态不为 `resolved` 和 `ignored` 的异常任务数量 | `exception_task` |
| 待确认动作数 | 当前需要用户确认的高风险动作数量 | `approval_instance`, `fulfillment_task` |
| 履约成功率 | 成功履约任务数 / 履约任务总数 | `fulfillment_task` |
| 物流回传成功率 | 成功回传物流记录数 / 应回传物流记录数 | `logistics_record` |
| 问答自动回复命中率 | 自动回复成功会话数 / 总咨询会话数 | `customer_conversation`, `customer_service_ticket` |
| 直播开播成功率 | 成功启动直播会话数 / 计划直播会话数 | `live_plan`, `live_session` |
| 库存预警命中率 | 被识别为低库存的商品数 / 已纳入库存监控的商品数 | `inventory_snapshot` |
| 补货任务完成率 | 已完成补货任务数 / 总补货任务数 | `replenishment_task` |
| 活动发布成功率 | 成功发布营销活动数 / 创建营销活动总数 | `campaign_activity` |
| 活动 ROI | 活动周期内增量销售额 / 活动成本 | `campaign_activity`, `finance_bill` |
| 会员复购率 | 周期内复购会员数 / 有过历史成交会员数 | `member_profile`, `order_main` |
| 账单生成及时率 | 按计划时间生成账单的次数 / 应生成账单次数 | `finance_bill` |
| 审批按时处理率 | 在承诺时限内处理完成的审批数 / 总审批数 | `approval_instance` |
| OpenAPI 调用成功率 | 成功调用次数 / 总调用次数 | `webhook_subscription`, 接口调用日志 |
| 试用转付费率 | 由试用租户转为正式付费租户的数量 / 总试用租户数量 | `tenant_subscription`, `billing_order` |
| 续费率 | 在到期前完成续费的订阅数 / 到期订阅总数 | `tenant_subscription`, `billing_order` |
| 租户流失率 | 周期内停用或取消订阅的租户数 / 周期初活跃租户数 | `tenant`, `tenant_subscription` |

## 5. 指标口径原则
- 指标必须有明确来源表、来源字段和统计周期。
- 同一指标在首页、分析页、报表页和导出文件中口径一致。
- 财务类指标必须标明是否含退款、平台费、运费和营销成本。
- 所有跨租户指标必须先完成租户隔离再做汇总，不允许跨租户原始明细直查。
- 指标口径变更必须保留版本记录，并同步更新数据质量与指标血缘文档。

## 6. 验收要求
- 前端埋点事件、后端业务日志和 BI 报表事件编码保持一致。
- 所有 P1 以上经营指标必须能够追溯到业务表和事实表。
- 关键事件必须带 `tenant_id`、`source_module`、`trace_id`。
- 回调、审批、导出、停服、支持介入等高风险事件必须同时写入审计链路。

## 7. 结论
这份文档已经把埋点、业务事件、经营指标和数据验收统一到一套正式口径中，可直接作为 BI 系统、驾驶舱、埋点改造和数仓开发的指标基线。
