## 1. 文档目的
本文档用于把现有 PRD、架构、数据、接口、测试和多租户设计文档收束为一份可直接指导研发执行的软件设计说明。

本文档重点回答以下问题：
- 平台按哪些系统边界组织开发
- 每个系统承担什么职责
- 多租户、权限、审计、订阅、计费如何落地
- 模型能力放在什么位置，如何与主系统解耦
- 研发阶段如何拆分，交付物如何对应

## 3. 系统目标与范围
### 3.1 总体目标
- 交付一套可按 SaaS 模式运营的多租户电商经营平台
- 打通订单、供应商、库存、客服、结算、经营分析主链路
- 支持标准版与私有化版双交付路径

### 3.2 系统边界
- `SaaS 平台底座`：租户、组织、权限、订阅、配额、计费、停复服、审计
- `OMS`：订单汇总、审单、履约编排、异常处理
- `SRM`：供应商档案、准入、评级、采购协同
- `ERP 基础能力`：库存、补货、采购、账单、结算、应收应付基础
- `CRM`：客服、售后、会员、复购运营
- `WMS/TMS`：仓储执行与运输跟踪的深化方向
- `BI`：指标口径、主题域、经营看板与分析输出
- `模型辅助层`：内容生成、回复建议、脚本生成、经营建议

### 3.3 非目标
- 本阶段不建设复杂微服务治理平台
- 本阶段不建设完全自助式 BI 平台
- 本阶段不建设租户自定义脚本执行引擎

## 4. 设计驱动因素
### 4.1 功能驱动
- 多租户 SaaS 交付
- OMS 主链路稳定
- SRM / ERP 基础协同
- CRM 服务闭环
- BI 指标可沉淀

### 4.2 质量属性驱动
- 安全性：隔离、脱敏、审计、受控介入
- 可维护性：模块边界清晰，职责明确
- 可扩展性：支持后续引入 WMS、TMS、BI 深化和外部集成
- 可测试性：主链路具备自动化回归能力
- 可观测性：全链路 `traceId`、任务日志、审计日志统一

### 5.2 外部系统

## 6. 容器与组件设计
### 6.1 容器划分
- Web 前端服务
- API 主服务
- 定时任务服务
- 队列消费者服务
- 模型接口适配服务
- 关系型数据库
- Redis
- 消息队列
- 对象存储
- 日志与监控服务

### 6.2 业务组件划分
- 认证与组织组件
- 店铺与渠道组件
- OMS 组件
- SRM 组件
- ERP 基础组件
- CRM 组件
- 审批与通知组件
- 开放平台组件
- 租户与订阅组件
- 平台运营组件
- 模型辅助组件

### 6.3 关键约束
- 平台侧与租户侧接口必须物理分层
- 所有主业务表必须显式带租户隔离维度
- Redis Key、导出路径、消息体必须包含租户信息
- 模型结果不能直接绕过业务校验和风控组件落库

## 7. 关键开发决策
### 7.1 架构形态
- 当前采用模块化单体优先
- 通过清晰包结构和领域边界控制复杂度
- 后续在连接器、模型、任务消费等方向预留拆分空间

### 7.2 多租户策略
- 采用共享应用、共享数据库、显式 `tenant_id` 隔离模式
- 租户侧查询范围以后端上下文为准
- 平台侧跨租户访问必须依赖支持会话或平台后台能力

### 7.3 模型辅助策略
- 模型能力只提供建议、生成和解释
- 违规、赔付、权限变更、订阅状态、财务结算等高风险结果必须人工兜底
- 提示词、模型版本、输入输出摘要必须留痕

## 8. 数据设计原则
- 租户是最高隔离边界
- 组织是协作边界
- 店铺是经营主体边界
- OMS、SRM、ERP、CRM 共享统一的基础主数据和审计体系
- BI 读取事实数据和汇总数据，不直接改写业务事实表

## 9. 接口设计原则
- 接口按系统域和使用方分组
- 所有写接口带 `traceId`
- 所有敏感接口强制审计
- 平台接口与租户接口分层命名
- 开放平台接口单独管理凭证和访问范围

## 10. 安全与治理设计
- 登录态校验
- 租户上下文校验
- 角色权限校验
- 组织范围校验
- 店铺范围校验
- 敏感字段脱敏展示
- 支持会话留痕
- 审计日志默认不可物理删除

## 11. 可观测性设计
- 必备标识：`traceId`、`tenant_id`、`organization_id`、`operator_type`
- 必备日志：应用日志、审计日志、任务执行日志、开放平台调用日志、订阅变更日志、配额命中日志
- 必备告警：回调失败、配额超限、消息堆积、越权访问、导出异常增长

## 12. 测试设计要求
### 12.1 P0 必测
- 租户隔离
- 日志导出隔离
- 订阅到期与停复服
- 配额超限拦截
- 回调幂等
- 订单履约异常补偿

### 12.2 专项回归
- OMS 状态流
- SRM/ERP 基础对账
- CRM 回复建议与转人工
- 模型提示词回归与降级

## 13. 研发分阶段实施方案
### 阶段一：SaaS 平台底座
- 登录认证
- 租户上下文
- 组织、角色、权限
- 审计日志
- 订阅、配额、计费基础能力

### 阶段二：业务主链路
- 店铺接入
- 商品与供应商
- 订单与履约
- 库存与补货
- 客服与售后

### 阶段三：经营主系统深化
- ERP 基础能力
- CRM 深化
- 审批与通知
- 开放平台

### 阶段四：执行与分析深化
- WMS / TMS 深化
- BI 建设
- 平台运营后台
- 私有化交付适配

- 后端模块骨架与分层结构
- 数据库建表脚本

## 15. 风险与待决策项
- 多租户隔离落地不彻底会直接影响商用版上线
- ERP 深化不足会限制库存、结算和利润核算能力
- BI 先于主数据稳定建设会造成口径反复调整
- 模型能力如果越过业务规则直接落库，会扩大治理风险

## 16. 结论
本 SDD 文档的目标，不是重复 PRD，而是把平台按可开发、可交付、可扩展的系统边界重新组织，为研发执行提供统一总纲。
