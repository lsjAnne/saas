## 3. 实体说明
### 3.1 SaaS 平台底座域
| 实体 | 含义 | 关键字段 | 约束/说明 |
| --- | --- | --- | --- |
| Tenant | SaaS 租户主体 | id, tenant_code, tenant_name, tenant_status, trial_end_at | 计费、隔离和平台运营的顶层对象 |
| Organization | 组织主体 | id, tenant_id, organization_name, status | 多团队协作基础对象 |
| OrganizationMember | 组织成员关系 | id, organization_id, user_id, user_name, mobile, role_code, status | 当前成员、角色与组织关系的主承载对象 |
| SubscriptionPlan | 套餐定义 | id, plan_code, plan_name, billing_type, seat_limit, feature_flags | 定义功能边界和配额上限 |
| TenantSubscription | 租户订阅关系 | id, tenant_id, plan_id, subscription_status, started_at, expired_at | 管理试用、正式订阅、续费和停服 |
| UsageQuota | 资源配额快照 | id, tenant_id, quota_code, quota_limit, used_amount, reset_at | 控制店铺数、成员数、API 调用量等 |
| BillingOrder | 计费订单 | id, tenant_id, plan_id, order_type, payable_amount, payment_status | 订阅、续费、升级、席位购买共用 |
| InvoiceRequest | 发票申请 | id, tenant_id, billing_order_id, invoice_title, invoice_status | 支撑商用化交付 |
| SupportSession | 支持会话 | id, tenant_id, reason, approver, expires_at, active | 平台受控介入租户业务链路的授权对象 |
| AuditLog | 审计日志 | id, tenant_id, organization_id, store_id, actor_id, action_type, target_type, target_id, operation_result, source_module, trace_id | 贯穿所有关键动作 |

### 3.2 店铺、渠道与供应链域
| 实体 | 含义 | 关键字段 | 约束/说明 |
| --- | --- | --- | --- |
| Store | 店铺主体 | id, tenant_id, organization_id, owner_user_id, platform_type, platform_shop_id, shop_name, auth_status | UNIQUE(owner_user_id, platform_type, platform_shop_id) |
| ChannelAccount | 渠道授权账号 | id, organization_id, channel_type, account_name, auth_status, expires_at | 一个组织可绑定多个渠道账号 |
| CandidateProduct | 候选商品池商品 | id, store_id, source_type, title, category, estimated_profit, risk_level | INDEX(store_id, status, updated_at) |
| Supplier | 供应商信息 | id, store_id, supplier_platform_type, supplier_platform_id, supplier_name, price_score, delivery_score, stability_score | 支持主备供应商标记 |
| ProductDraft | 商品草稿 | id, store_id, candidate_product_id, title, selling_points, detail_content, suggested_price | 记录生成结果和状态 |
| Product | 正式商品 | id, store_id, platform_product_id, product_draft_id, title, status, health_score | UNIQUE(store_id, platform_product_id) |
| ProductSourceMapping | 商品与货源映射关系 | id, store_id, product_id, supplier_id, mapping_type, is_active | 支持主货源和备用货源 |
| SKU | 平台商品 SKU | id, product_id, sku_code, spec_text, price, stock | UNIQUE(product_id, sku_code) |
| SKUMapping | SKU 与货源规格对应关系 | id, product_source_mapping_id, product_sku_id, supplier_sku_code, mapping_status | 记录映射校验状态 |
| InventorySnapshot | 库存快照 | id, store_id, product_id, sku_id, available_stock, reserved_stock, safety_stock | 支撑库存预警与补货建议 |
| ReplenishmentTask | 补货/采购任务 | id, store_id, product_id, sku_id, suggested_qty, task_status, approval_status | 支持审批流与采购协同 |
| ContentAsset | 内容素材对象 | id, store_id, asset_type, asset_name, asset_url, version_no, source_type | 用于商品图文、直播素材、客服模板 |

## 4. 实体关系
- 一个 Tenant 对应多个 Organization、TenantSubscription、UsageQuota、BillingOrder、InvoiceRequest、SupportSession 和 AuditLog。
- 一个 Organization 对应多个 Store、ChannelAccount、OrganizationMember、NotificationTask、ApprovalInstance 和 PluginApp。
- 一个 SubscriptionPlan 可被多个 TenantSubscription 和 BillingOrder 引用。
- 一个 Store 对应多个 CandidateProduct、Supplier、ProductDraft、Product、Order、CustomerConversation、CampaignActivity、MemberProfile 和 FinanceBill。
- 一个 Product 可绑定多个 ProductSourceMapping、SKU、FAQKnowledge、InventorySnapshot 和 ContentAsset。
- 一个 SKU 可对应多个 SKUMapping，并参与库存快照、补货任务和订单明细。
- 一个 Order 对应多个 OrderItem，可生成多个 FulfillmentTask、AfterSaleRecord 和 CustomerServiceTicket。
- 一个 CustomerConversation 对应多个 ConversationMessage。
- 一个 MemberProfile 可绑定多个 MemberTag，并可与订单和营销活动产生关联。
- 一个 LivePlan 对应多个 LiveScript、LiveSession 和 LiveConcurrencyQueue。
- 一个 LiveAccount 可被多个 LivePlan 和 LiveSession 引用，但同一时刻只允许一个 running 会话占用。
- 一个 LiveSession 可对应多个 LiveRiskEvent、LiveInteractionEvent、LiveSceneSwitchRecord、LiveManualTakeoverRecord 和 LiveCommitmentAudit。
- 一个 LiveSceneTemplate 可被多个 LivePlan 引用，并驱动多个 LiveSceneSwitchRecord。
- 一个 FinanceBill 可生成多个 SettlementRecord。
- 一个 PluginApp 可拥有多个 IntegrationCredential，并可订阅多个 WebhookSubscription。

## 6. 结论
数据模型必须同时围绕主业务交易链路和商用 SaaS 治理能力设计。

前者保证系统能跑通店铺、商品、订单、履约、异常、客户服务和财务链路；
后者保证系统能持续扩展为多租户、多组织、可订阅计费、可审计追责、可对外开放的正式商用平台。
