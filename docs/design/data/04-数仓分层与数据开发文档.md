## 1. 文档目的
本文档用于定义项目的数据仓库分层架构、源数据范围、主题域、事实表、维度表、宽表、时效要求和交付物标准，作为 BI 系统和经营分析体系建设的正式数据基线。

## 2. 数据仓库定位
- 统一业务库、埋点、回调、审计和模型结果的统计口径。
- 支撑驾驶舱、经营分析、订阅分析、客服分析、直播分析和财务复盘。
- 降低直接查询业务库的风险，隔离线上交易链路与分析链路。
- 为 BI 看板、报表导出、模型评估和数据服务提供稳定底座。

## 9. 分区、主键与同步要求
### 9.1 分区与主键
- 日级事实表按 `dt` 分区。
- 高频事件表按 `dt + hour` 分区。
- 汇总表按统计周期分区。
- 主键优先使用业务主键加日期分区，不依赖纯自增键做分析去重。

### 9.2 同步与增量
- 业务库优先使用 CDC。
- 埋点数据优先使用消息或日志采集。
- 第三方回调日志原样进入 ODS。
- 增量同步优先按 `updated_at` 或 Binlog 位点。
- 删除事件必须保留删除标记。
- 迟到数据允许回刷并保留补算记录。

## 10. 时效与服务要求
| 场景 | 时效要求 |
| --- | --- |
| 驾驶舱核心指标 | T+0 或准实时 |
| 经营分析 | T+1 |
| 财务复盘 | T+1 或 T+2 |
| SaaS 运营分析 | T+1 |
| 数据服务导出 | 以最新完成批次为准 |

## 11. 质量与验收要求
- 订单口径以标准化订单 `order_main` 为准。
- 销售额口径必须明确是否含退款、运费、平台费。
- 毛利口径必须明确成本构成。
- 活动 ROI 必须明确活动成本口径。
- 直播指标必须区分计划场次和实际场次。
- 所有跨租户统计必须先完成租户隔离。
- 指标结果表必须能回溯到事实表和来源业务表。
