## 1. 文档目的
本文档用于统一系统中高频公共枚举值的定义、含义、适用字段和使用约束，避免前端、后端、测试、数据和模型能力模块各自维护不同口径。

说明：
- 状态流转规则以 [状态机说明文档](../architecture/02-状态机说明文档.md) 为准。
- 字段所在表以 [数据库表结构设计文档](02-数据库表结构设计文档.md) 为准。
- 本文档重点回答“枚举值有哪些、分别代表什么、哪些模块共用”。

## 2. 使用原则
- 枚举值统一使用英文小写加下划线格式。
- 前端显示文案可中文化，但传输值和存储值必须使用标准枚举值。
- 同名字段优先复用同一套枚举，不轻易新增近义值。
- 新增枚举值必须同步更新状态机、数据字典、接口文档和测试用例。

## 4. 状态类公共枚举
### 4.1 授权状态 `auth_status`
适用字段：
- `store.auth_status`
- `channel_account.auth_status`

| 枚举值 | 中文含义 | 说明 |
| --- | --- | --- |
| `connected` | 已连接 | 授权有效，可正常访问平台能力。 |
| `disconnected` | 未连接 | 未完成授权或已断开。 |
| `expired` | 已过期 | 授权已失效，需要重新授权。 |
| `error` | 授权异常 | 授权过程或调用过程出现异常。 |

### 4.2 通用启用状态 `status`
适用字段：
- `organization.status`
- `subscription_plan.status`
- `coupon_template.status`
- `plugin_app.status`
- `webhook_subscription.status`

| 枚举值 | 中文含义 | 说明 |
| --- | --- | --- |
| `active` | 生效中 | 适用于组织等业务对象处于可用状态。 |
| `enabled` | 已启用 | 适用于配置、插件、套餐、订阅类对象可用。 |
| `disabled` | 已停用 | 对象被停用但未删除。 |
| `inactive` | 未激活 | 预留给未生效对象。 |

说明：
- `active` 更偏业务实体生效状态。
- `enabled` 更偏配置、开关、能力启用状态。
- 同一字段不要同时混用 `active` 和 `enabled`。

## 6. 风险与优先级类枚举
### 6.1 风险等级 `risk_level`
适用字段：
- `candidate_product.risk_level`
- `supplier.risk_level`
- `live_risk_event.risk_level`
- `live_interaction_event.risk_level`

| 枚举值 | 中文含义 | 说明 |
| --- | --- | --- |
| `low` | 低风险 | 可接受风险。 |
| `medium` | 中风险 | 需要关注。 |
| `high` | 高风险 | 需要重点审查。 |
| `critical` | 极高风险 | 必须立即阻断或人工接管。 |

### 6.2 异常严重级别 `severity`
适用字段：
- `exception_task.severity`

| 枚举值 | 中文含义 | 说明 |
| --- | --- | --- |
| `P0` | 阻断级 | 严重阻断主链路。 |

| `P2` | 中优先级 | 一般业务异常。 |
| `P3` | 低优先级 | 低影响问题。 |

## 7. 枚举治理要求
- 枚举值必须在接口层和数据库层保持一致。
- 前端枚举展示文案应统一从配置层维护，不要散落硬编码。
- 测试用例必须覆盖每个核心枚举值的正向和异常场景。
- 数据团队在数仓和报表中不得自行翻译出第二套状态值。
