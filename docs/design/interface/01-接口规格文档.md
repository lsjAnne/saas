## 1. 文档目的

定义当前后端接口的统一约定、返回结构、核心行为约束与已落地接口范围，供开发、联调、测试与验收共用。

## 2. 通用约定

- 接口统一使用 JSON 传输。
- 租户侧与平台后台接口默认使用 Bearer token，`tenantId`、`organizationId`、`storeId` 以后端登录态和权限解析结果为准，不以前端传参为准。
- 租户后台开放平台管理接口 `GET/POST /api/open/apps`、`GET/POST /api/open/webhooks`、`GET /api/open/logs` 仍使用租户登录态；外部应用读取接口 `/api/open/external/**` 使用 `X-Open-App-Key` / `X-Open-App-Secret` 进行凭据认证。
- 开放平台外部 ERP 读取接口在凭据认证通过后，还必须校验应用 `permissionScope`；当前 `/api/open/external/erp/*` 统一要求 `finance.read`。
- 列表接口默认支持分页参数 `page`、`pageSize`。
- 所有资源主键均使用系统编码后的字符串 ID。
- 所有写操作都应形成审计记录或业务日志。
- 全局响应需要返回 `traceId` 便于问题追踪。

## 3. 通用响应结构

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "string"
}
```

## 5. 关键行为约束

### 5.1 通知中心

- 通知任务列表仅返回当前租户数据，默认按创建时间倒序。
- `notifyType` 必须与模板渠道一致。
- 当前支持渠道：`site_message`、`sms`、`email`、`feishu_bot`。
- 当前支持优先级：`low`、`normal`、`high`、`urgent`。
- `batch-send` 用于同模板多接收人批量投递。
- `run-due` 用于执行当前租户已到期的定时通知。
- `targetReceiver` 包含 `fail` 或 `payloadJson` 包含 `"forceFail":true` 时，首次发送标记为 `failed`。
- 重试仅允许针对 `failed` 任务执行，成功后状态更新为 `sent` 且 `retryCount + 1`。
- 定时通知重复调度失败达到 3 次后转入 `dead_letter`。

### 5.2 审批中心

- 审批对象当前承接补货任务、售后单和直播高风险承诺三类业务对象。
- 审批通过、驳回、转交都需要产生审计记录。
- 审批流转同时驱动通知中心自动生成系统通知。
- 直播高风险承诺审批通过后，必须回写 `live_commitment_audit.audit_status=approved` 或触发对应履约跟踪动作。

### 5.3 营销活动中心

- 活动状态流转基线为：`draft -> pending_approval -> approved -> published`。
- 审批驳回后活动状态回写为 `rejected`。
- 优惠券模板与活动分析能力已纳入当前基线。

### 5.4 会员中心

- 会员标签增删仅允许在当前租户、当前门店范围内执行。
- 人群导出任务按筛选条件生成结果，默认用于运营分析与触达准备。
- 会员分析结果由经营看板统一聚合展示。

### 5.5 财务中心

- 账单生成、对账、结算必须按租户和门店归属校验。
- 对账与结算属于有审计要求动作，必须保留操作记录。
- 当前接口基线不包含单独的 `settlement-records` 查询接口。

### 5.6 经营看板

- `summary` 用于经营总览指标聚合。
- `trends` 用于趋势分析与时间序列展示。
- `risks` 用于风险识别与运营预警。
- `campaign-analysis` 对接营销活动表现。
- `member-analysis` 对接会员活跃、复购与分层分析。

### 5.7 直播高级治理

- `live-sessions/{id}/status` 必须返回控场模式、当前场景、下一候选场景、待确认承诺数、人工接管标记等运行态字段。
- `switch-scene` 为异步切换接口，首次响应只返回切换受理结果，最终结果以切换记录或状态接口为准。
- `enable-control-mode` 仅允许取值 `standard`、`enhanced`、`manual`。
- `manual-takeover` 成功后，`live_session.session_status` 必须切换为 `manual_takeover`。
- `commitments/confirm` 与 `commitments/reject` 必须绑定承诺审计记录，不允许无留痕处理。
- 高风险问答命中后，`interaction/reply` 不允许绕过风险校验直接自动回复。

### 5.8 开放平台安全约束

- `/api/open/apps` 创建应用时必须提供非空 `permissionScope`，并与应用实际访问范围保持一致。
- `/api/open/webhooks/{id}/secret/rotate` 轮换成功后，新旧回调签名不可混用，旧签名请求必须被拒绝。
- `/api/open/callbacks/{id}` 必须校验 `X-Open-Request-Id`、`X-Open-Timestamp`、`X-Open-Nonce`、`X-Open-Signature`，并执行签名校验、5 分钟时间窗校验与防重放校验。
- `/api/open/external/profile` 只负责外部应用凭据认证与租户归属识别，不放开业务数据访问。
- `/api/open/external/erp/*` 必须在凭据认证后继续校验 `finance.read` scope；缺少 scope 时返回 `1009`，并记录 `rejected_scope` 调用日志。

## 6. 错误与审计要求

- 业务校验失败返回统一业务异常编码与消息。
- 未找到资源时返回统一对象不存在错误。
- 租户侧写接口应记录后端解析得到的 `tenantId`、操作者、目标对象、时间与结果，不以前端传入值为准。
- 开放平台关键调用应记录 `tenantId` 或 `tenant_id`、应用标识、结果状态、`traceId` 和拒绝原因，便于抽查 `rejected_secret`、`rejected_replay`、`rejected_scope` 等安全事件。
- 涉及通知、审批、财务的关键动作必须可追溯。
- 直播高级治理接口除通用错误外，还必须返回明确的直播专项错误码，禁止只返回模糊文本消息。

### 6.1 直播专项错误码
| 错误码 | 错误消息建议 | 触发场景 | 处理要求 |
| --- | --- | --- | --- |
| `7101` | `live account occupied` | 直播账号已被其他会话占用 | 返回占用账号、占用会话和建议重试方式 |
| `7102` | `live concurrency quota exceeded` | 租户直播并发配额不足 | 返回 `quotaCode=live_concurrency` 和当前余量 |
| `7103` | `live scene switch failed` | 场景切换执行失败 | 返回切换记录 ID 与是否已进入回退流程 |
| `7104` | `live scene rollback failed` | 场景回退失败 | 必须提示人工接管要求 |
| `7105` | `manual takeover required` | 风险等级过高或连续异常 | 返回建议接管类型和关联风险事件 |
| `7106` | `commitment blocked` | 命中禁止承诺 | 返回承诺类型、风险等级和阻断原因 |
| `7107` | `commitment approval required` | 命中需人工确认承诺 | 返回审批单 ID 或待确认标记 |
| `7108` | `interaction transfer timeout` | 转人工超时未处理 | 返回目标角色和超时时间 |
