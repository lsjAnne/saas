## 1. 文档目的
本文档用于定义“直播运营中心”的业务目标、覆盖边界、角色分工、核心流程、页面结构、数据模型、风控策略、接口设计和验收标准，作为直播专项能力实施、测试和交付的依据。

## 2. 业务目标
- 让缺少专业直播团队的租户也能开展标准化直播带货
- 自动完成直播计划、直播脚本、商品讲解、评论应答和直播运行
- 让直播能力与商品、库存、价格、客户服务、审批、通知和 BI 分析联动
- 让直播过程可监控、可暂停、可中止、可接管、可回放
- 在风控边界内支持高互动性强控场直播，达到接近真人直播节奏、互动效果和控场表现
- 对极复杂场景切换和高风险销售承诺场景提供分级治理、人工确认和人工接管能力

## 3. 适用场景
适合：
- 固定时间段商品讲解直播
- 标准化商品轮播直播
- 新品介绍直播
- 清库存或活动商品直播
- 高互动问答直播
- 强节奏控场直播
- 多轮活动串场直播
- 大促预热、秒杀、返场、抽奖、催付等复杂场景切换直播

纳入覆盖但分级处理：
- 高互动型强控场直播
  说明：由系统优先执行标准节奏与标准问答，超出阈值时转人工场控或人工主播接管
- 极复杂场景切换
  说明：通过场景模板、切换编排、状态回退和人工确认实现，不允许无约束自由切换
- 高风险人工销售承诺场景
  说明：系统只允许在白名单承诺范围内自动表达，超出范围必须人工确认或人工发声

不纳入自动化表达：
- 违反平台规则、广告规范、价格规则或消费者权益要求的承诺
- 医疗疗效、投资收益、绝对最低价、绝对时效、绝对赔付等无法自动履约或无法验证的内容

## 4. 系统角色
- 运营人员：创建直播计划、选商品、审核脚本、配置场景和活动节奏
- 场控人员：管理直播节奏、切换场景、处理互动高峰、触发人工接管
- 人工主播：在高风险、高复杂度或高情绪波动场景下接管直播表达
- 客服坐席：承接售后、履约、订单和敏感问答升级处理
- 风控审核人员：审核高风险脚本、审批特殊承诺、复核异常事件
- 系统：生成脚本、编排直播、分发互动任务、监控状态
- 直播执行引擎：执行讲解、播报、场景切换和基础互动回复
- 风控系统：审核话术、监控商品状态、识别承诺风险和异常行为
- 审批中心：承接特殊承诺、特殊价格、赠品、补偿和异常履约审批

## 4.1 并发控制规则
- 同一个直播账号同一时间只允许 1 场直播会话处于 `running` 状态
- 同一个店铺绑定多个直播账号时，允许多个直播会话并行运行
- 同一个租户的直播并发场次由套餐配额控制，不在代码中写死固定上限
- 当账号占用或套餐配额不足时，开播动作必须失败并给出明确原因，或进入排队状态
- 并发校验必须发生在手动开播、定时开播和恢复开播三个场景
- 高互动场次应支持预留人工接管席位，人工接管不额外占用直播并发配额，但应记录接管资源占用

## 4.2 设计控制原则
- 系统优先完成标准化表达，人工只处理风险、复杂度或情绪强度超阈值场景
- 所有高风险承诺必须留痕，包括触发原因、确认人、确认时间、承诺内容和后续履约要求
- 场景切换必须有前置条件、回退条件和回退动作，不允许无状态切换
- 直播中的自动表达必须受商品状态、库存、价格、审批结果和风控策略实时约束
- 验收目标为“接近真人直播运营效果”，不是“完全无法区分真人与系统”

## 5. 核心流程
### 5.1 直播计划流程
1. 选择店铺
2. 创建直播计划
3. 选择直播时间
4. 选择直播商品池
5. 配置主播形象、声音和互动风格
6. 配置直播场景模板、节奏策略和互动阈值
7. 生成直播脚本
   说明：已绑定商品时，脚本按绑定顺序生成 `Segment 01/02/...` 讲解片段；未绑定商品时，仍允许生成通用脚本
8. 审核脚本、场景切换和承诺白名单
9. 发布计划

### 5.2 开播流程
1. 到达计划时间
2. 系统执行直播前检查
3. 检查商品状态、库存、价格、脚本审核结果和风控结果
4. 检查直播账号是否被占用、店铺是否满足并发条件、租户套餐配额是否足够
5. 加载直播场景模板、互动阈值和高风险承诺白名单
6. 启动直播运营
7. 推进讲解节奏
8. 接收直播评论、互动指令和订单动向
9. 联动客户服务辅助能力、风控能力和人工接管机制

### 5.3 高互动问答流程
1. 接收评论、弹幕、催单、异议、价格询问和活动问答
2. 系统按问题类型做标准问答、商品问答、价格问答和履约问答分类
3. 命中低风险标准答案时自动回复
4. 命中敏感问答、重复追问、高情绪投诉或高价值客户时进入人工待处理队列
5. 若互动峰值超过阈值，场控人员可启用“强控场模式”
6. 强控场模式下，系统优先发出节奏引导、活动提示、下单催化和评论聚焦语句
7. 超出承诺边界的问题必须转人工主播或客服坐席确认后再回复

### 5.4 复杂场景切换流程
1. 直播按主场景启动，如新品主推、秒杀、返场、抽奖、连麦答疑
2. 系统持续监听库存变化、订单转化、评论热点、风险事件和运营指令
3. 满足切换条件时，进入目标场景预加载
4. 执行场景切换前校验脚本、商品、价格、库存、资源和风控约束
5. 切换成功后更新当前场景、当前脚本段、互动策略和页面提示
6. 若切换失败，则回退到上一个稳定场景，并记录失败原因
7. 连续切换失败达到阈值时，自动触发人工场控确认或人工主播接管

### 5.5 高风险销售承诺确认流程
1. 系统识别直播话术、评论追问或运营输入中的承诺意图
2. 承诺意图按白名单承诺、需审批承诺、禁止承诺三类分级
3. 白名单承诺可自动表达，并记录命中策略
4. 需审批承诺进入人工确认流程，待风控审核人员、场控人员或授权运营确认
5. 禁止承诺直接拦截，页面提示风险原因并禁止播报
6. 人工确认通过后，系统方可执行指定承诺话术或交由人工主播发声
7. 承诺执行后，生成履约跟踪任务，联动客服、订单和履约模块

### 5.6 异常处理与人工接管流程
1. 检测到直播风险、价格异常、库存不足、评论失控、场景切换失败或平台异常
2. 系统根据事件等级执行告警、降级、暂停、终止或人工接管
3. 高等级风险事件进入人工接管区
4. 场控人员或人工主播确认接管后，系统切换为人工主导模式
5. 风险解除后，可选择恢复系统直播或结束直播
6. 生成异常记录、接管记录和后续复盘任务

## 6. 页面设计
### 6.1 直播计划列表页
展示：
- 计划名称
- 计划状态
- 直播时间
- 商品数量
- 主播配置
- 直播账号
- 并发占用状态
- 场景模板
- 高互动模式开关

动作：
- 创建计划
- 编辑计划
- 复制计划
  说明：复制后的新计划应继承原计划已绑定商品，但不继承原脚本版本与运行态
- 停止计划

### 6.2 直播计划详情页
展示：
- 基础信息
- 商品池
- 直播脚本
- 场景模板与切换编排
- 互动阈值
- 承诺白名单与审批要求
- 风控结果
- 历史直播记录

动作：
- 生成脚本
- 审核脚本
- 审核场景切换
- 配置承诺白名单
- 启动直播
- 暂停直播
- 结束直播
  说明：若计划已存在激活脚本，绑定或解绑商品后需自动重建新的激活脚本版本，避免讲品脚本与已绑定商品集合不一致

### 6.3 直播运行页
展示：
- 当前直播状态
- 当前讲解商品
  说明：状态接口需返回 `currentProductId`、`currentProductTitle`、`currentProductSourceType`，用于运行页直接展示当前正在讲解的绑定商品
- 当前脚本片段
- 当前场景与下一候选场景
- 直播时长
- 实时互动区
  说明：展示评论流、热点问题、待处理高风险问答、互动峰值告警
- 场控区
  说明：支持切换节奏模式、切换场景、插播提示、活动催化
- 人工接管区
  说明：支持场控接管、人工主播接管、接管原因记录、恢复系统直播
- 风险承诺提示区
  说明：展示被拦截承诺、待确认承诺、已确认承诺和履约跟踪状态
- 风险告警
- 当前账号占用信息
- 当前租户剩余并发配额

动作：
- 暂停
- 跳过当前商品
  说明：若已绑定商品，则跳转到下一绑定商品片段；若未绑定商品，则沿用通用脚本文本前进逻辑
- 切换场景
- 启用强控场模式
- 转人工回复
- 确认承诺
- 拒绝承诺
- 人工接管
- 恢复系统直播
- 结束直播

## 7. 数据对象
基础对象：
- `live_plan`
- `live_product_item`
- `live_session`
- `live_script`

治理对象：
- `live_account`
  说明：直播账号、账号状态、占用状态、适用平台、授权信息
- `live_risk_event`
  说明：直播风险事件、风险等级、处置动作、处置人、处置结果
- `live_concurrency_queue`
  说明：并发不足时的排队申请、占用释放和重试记录

扩展对象：
- `live_interaction_event`
  说明：评论、弹幕、问答、催单、异议、互动分类、风险等级、回复结果
- `live_scene_template`
  说明：场景模板、切换条件、回退条件、节奏参数、插播规则
- `live_scene_switch_record`
  说明：场景切换动作、前后场景、触发来源、切换结果、回退结果
- `live_manual_takeover_record`
  说明：人工接管人、接管类型、接管原因、起止时间、恢复方式
- `live_commitment_audit`
  说明：承诺内容、承诺分类、审批状态、确认人、履约要求、关联订单

### 7.1 关键对象字段约束
| 对象 | 关键字段 | 设计要求 |
| --- | --- | --- |
| `live_account` | `tenant_id`, `store_id`, `channel_type`, `account_code`, `auth_status`, `occupancy_status`, `last_heartbeat_at` | 必须支持账号授权状态、占用状态和心跳检测，不允许同账号双占用 |
| `live_risk_event` | `live_session_id`, `risk_type`, `risk_level`, `trigger_source`, `dispose_action`, `event_status` | 必须记录风险来源、处置动作、处置人和处置结果 |
| `live_concurrency_queue` | `live_plan_id`, `live_account_id`, `queue_status`, `requested_at`, `granted_at`, `retry_count` | 必须支持排队、授权、超时、取消四类排队状态 |
| `live_interaction_event` | `event_type`, `message_text`, `customer_id`, `risk_level`, `reply_status`, `transfer_status` | 必须支持评论、弹幕、问答、催单、转人工留痕 |
| `live_scene_template` | `template_code`, `scene_type`, `trigger_rule_json`, `rollback_rule_json`, `is_enabled` | 必须可配置触发条件、回退条件和节奏参数 |
| `live_scene_switch_record` | `from_scene_code`, `to_scene_code`, `switch_status`, `trigger_source`, `rollback_status` | 必须记录切换前后场景、触发来源、切换结果和回退结果 |
| `live_manual_takeover_record` | `takeover_type`, `operator_id`, `takeover_reason`, `started_at`, `ended_at`, `takeover_status` | 必须支持场控接管、主播接管和恢复系统直播闭环 |
| `live_commitment_audit` | `interaction_event_id`, `commitment_type`, `commitment_level`, `commitment_text`, `audit_status`, `approved_by`, `approval_id` | 必须记录承诺分级、审批结果和履约跟踪要求 |

## 9. 风控要求
### 9.1 直播前风控
- 商品必须可售
- 库存必须满足最低阈值
- 价格不能异常倒挂
- 直播脚本必须通过内容审核
- 场景模板必须完成切换校验和回退校验
- 高风险承诺白名单必须完成审批

### 9.2 直播中风控
- 当前商品缺货时禁止继续讲解
- 当前商品价格波动超过阈值时暂停讲解
- 敏感评论问题不自动扩展承诺
- 检测到账号掉线或平台强制下播时自动标记异常并尝试恢复或转人工
- 评论流量、负面情绪或争议问题超过阈值时，自动提示场控进入强控场模式
- 连续场景切换失败时，自动回退到稳定场景并触发人工确认

### 9.3 禁止自动表达的承诺
- 绝对最低价、全网最低价、保价无条件生效
- 必到时效、必定当天发出、必定次日达
- 疗效、功效、收益、减肥、医疗或投资性质保证
- 未经审批的赠品、赔付、补贴、折上折、特殊价格
- 超出平台规则或公司履约能力的退款、退换、补偿承诺

### 9.4 必须人工确认的承诺
- 特批价格、临时优惠、补贴叠加
- 延迟发货说明、补发说明、履约兜底方案
- 赠品补发、差价补偿、售后补偿
- 特殊客户定向承诺
- 涉及品牌授权、官方资格、保真、保修的敏感表述

### 9.5 直播后风控
- 记录所有直播状态变化
- 记录所有中断原因
- 保存直播摘要、互动摘要、承诺摘要和异常摘要
- 对已确认承诺生成履约跟踪任务，并校验是否按承诺执行

## 10. 与其他模块联动
- 与商品中心联动：读取商品标题、卖点、详情、讲解优先级
- 与库存和 ERP 联动：校验可售库存、安全库存、锁库策略、补货信息
- 与价格中心联动：校验直播价、活动价、限时价和价盘审批结果
- 与客户服务辅助能力联动：处理直播评论高频问答、售后升级和人工客服转派
- 与审批中心联动：处理特殊承诺、特批价格、补偿和异常履约审批
- 与风控中心联动：处理内容风险、承诺风险、直播风险和异常事件分级
- 与通知中心联动：推送风险告警、接管提醒、审批提醒和异常结果
- 与 BI 分析系统联动：输出直播转化、互动、控场、承诺和履约指标
- 与驾驶舱联动：展示直播相关数据、异常、人工接管和经营贡献

## 13. 验收标准
- 能创建直播计划
- 能生成直播脚本
- 能启动和停止直播
- 能识别直播异常
- 能记录直播过程和结果
- 直播中商品风险变化可触发告警或中止
- 同一直播账号重复开播时能被系统拦截
- 同店多账号并发直播时状态、日志和风控信息正确
- 租户套餐配额超限时能正确阻止开播或进入排队
- 能支持高互动问答分流、热点聚焦和强控场模式切换
- 能支持复杂场景切换、失败回退和人工确认
- 能对高风险销售承诺执行拦截、人工确认和履约留痕
- 在风控范围内达到接近真人直播运营效果，具备可度量的互动、节奏和接管指标

## 13.1 自动化测试要求
- 必须具备直播计划、脚本生成、开播、暂停、结束的接口自动化测试
- 必须具备直播账号占用冲突、店铺多账号并发、租户并发超限的回归测试
- 必须具备直播状态回调模拟测试，验证开播成功、异常中断、暂停恢复三类场景
- 必须具备已绑定商品脚本分段生成与跳过当前商品切换到下一绑定商品的回归测试
- 必须具备直播状态详情返回当前讲解商品字段，并在跳品后同步切换当前商品的回归测试
- 必须具备高互动评论分类、自动回复、转人工回复和强控场模式切换测试
- 必须具备场景切换成功、切换失败回退、连续失败转人工的测试
- 必须具备承诺白名单命中、需人工确认、禁止承诺拦截三类测试
- 必须具备人工接管、恢复系统直播和接管记录留痕测试
- 每次发布前必须执行直播专项自动化回归并输出结果

## 14. 结论
直播运营中心不是只做基础讲品能力，而是要形成“标准化直播执行 + 高互动控场 + 风险分级治理 + 人工接管兜底”的完整能力闭环。系统目标是在合规和可履约前提下，尽可能接近真人直播运营节奏与互动效果；对超出自动化边界的承诺和复杂场景，必须由人工确认或人工接管完成。
