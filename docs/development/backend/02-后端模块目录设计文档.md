## 1. 文档目的
本文档基于 [SDD开发设计文档](../../design/architecture/10-SDD开发设计文档.md)，给出后端代码目录、模块边界、包结构、命名规范和落地顺序，用于指导后端工程初始化和后续功能开发。

## 2. 设计目标
- 以模块化单体方式组织后端代码
- 让业务模块、SaaS 模块、公共支撑模块边界清晰
- 让多租户、权限、审计、任务、连接器等横切能力可复用
- 为未来拆分服务保留清晰边界

## 3. 工程建议
### 3.1 仓库级建议
- 使用单 Maven 根工程
- 根工程负责依赖管理、插件管理、统一版本
- 业务模块与启动模块分离

### 3.2 模块组织建议
- `platform-dependencies`：依赖版本管理
- `platform-common`：公共工具、异常、枚举、结果对象
- `platform-infra`：数据库、缓存、消息队列、对象存储、审计基础设施
- `platform-domain`：领域层模块聚合
- `platform-application`：应用服务层模块聚合
- `platform-interfaces`：HTTP、回调、消息消费接口层
- `platform-bootstrap`：启动模块

如果先不拆多 Maven 子模块，也至少要在单模块内按上述逻辑拆包，避免所有代码混在一个目录里。

## 5. 包分层规范
每个业务模块下推荐使用统一分层：

```text
modules/{module}
├─ controller
├─ application
├─ domain
│  ├─ model
│  ├─ service
│  ├─ event
│  └─ repository
├─ infrastructure
│  ├─ persistence
│  ├─ convert
│  └─ external
└─ dto
```

说明：
- `controller`：只做参数接收、权限入口、结果返回
- `application`：负责编排流程、事务边界、跨模块调用
- `domain.model`：实体、值对象、聚合根
- `domain.service`：领域规则
- `domain.repository`：领域层仓储接口
- `infrastructure.persistence`：数据库实现
- `infrastructure.external`：第三方连接器实现
- `dto`：请求响应对象、命令对象、查询对象

## 6. 公共支撑模块设计
### 6.1 `common`
- `api`：统一返回结构
- `exception`：业务异常、系统异常
- `enums`：公共枚举
- `utils`：时间、JSON、脱敏、集合等工具
- `constants`：公共常量

### 6.2 `infra`
- `db`：MyBatis/JPA 配置、分页、审计字段填充
- `redis`：缓存客户端与 Key 构建器
- `mq`：消息生产者、消费者基类
- `storage`：对象存储封装
- `idempotent`：幂等辅助

### 6.3 `support`
- `tenant`：租户上下文、租户解析器、租户校验器
- `security`：鉴权、角色权限、数据范围
- `audit`：审计日志记录器、审计注解、导出留痕
- `risk`：风控校验组件
- `trace`：`traceId` 透传与日志上下文
- `export`：导出任务抽象
- `supportsession`：平台支持会话模型与校验

## 7. 核心业务模块职责
### 7.1 `auth`
- 登录、退出、当前用户信息
- Token 校验与刷新
- 登录态与租户态桥接

### 7.2 `tenant`
- 租户创建、试用开通、停复服
- 租户状态管理
- 租户基础档案

### 7.3 `organization`
- 组织、成员、角色、权限绑定
- 组织范围和店铺范围控制

### 7.4 `store`
- 店铺接入、授权、配置
- 店铺状态与默认经营参数

### 7.5 `channel`
- 渠道账号、平台授权刷新
- 多平台接入状态维护

### 7.6 `product`
- 候选商品、商品草稿、正式商品
- 货源映射、SKU 映射、内容素材关联

### 7.7 `supplier`
- 供应商、主备供应商、价格库存读取入口

### 7.8 `inventory`
- 库存快照、补货建议、补货任务

### 7.9 `order`
- 订单主单、订单明细、订单同步

### 7.10 `fulfillment`
- 履约任务、物流回传、履约重试

### 7.11 `exception`
- 异常识别、人工关闭、升级、忽略

### 7.12 `servicecase`
- 客服工单、售后记录、人工处理流程

### 7.13 `qa`
- FAQ、会话、消息、回复建议、风控留痕

### 7.14 `live`
- 直播计划、直播会话、直播脚本、并发配额校验

### 7.15 `campaign`
- 营销活动、优惠券模板、触达策略

### 7.16 `member`
- 会员档案、标签、分群建议

### 7.17 `finance`
- 财务账单、结算记录、SaaS 计费订单、发票申请

### 7.18 `approval`
- 审批实例、高风险动作审批

### 7.19 `notification`
- 站内信、短信、邮件、飞书等通知任务

### 7.20 `openplatform`
- 开放应用、回调订阅（Webhook）、开放平台调用日志

### 7.21 `saas`
- 套餐定义、租户订阅、席位、配额、续费升级降级

### 7.22 `admin`
- 平台管理、系统设置、租户运营、平台审计、支持会话（support session）

### 7.23 `metrics`
- 驾驶舱指标、经营快照、运营指标聚合

## 8. 跨模块调用原则
- 同一模块内部优先通过领域服务调用
- 跨模块优先通过应用服务调用
- 异步流程优先通过领域事件或消息队列
- 禁止 Controller 直接依赖别的模块 Repository
- 禁止绕过租户上下文直接访问他模块持久层

## 12. 第一阶段落地最小目录
平台底座阶段建议先建这些目录：

```text
modules
├─ auth
├─ tenant
├─ organization
├─ saas
├─ admin
└─ order

support
├─ tenant
├─ security
├─ audit
├─ trace
└─ supportsession
```

当前实现进度：
- 平台底座与主链路中，`auth`、`organization`、`store`、`tenant`、`admin`、`saas` 已完成 `controller` / `application` 子包收口。
- 增长与经营分析相关的 `member`、`finance`、`dashboard` 也已完成同样的包收口，当前采用“内聚包级 `record`，暂不新增 DTO 文件”的过渡策略对齐标准骨架。
- 主链路与增长扩展中的 `campaign`、`inventory`、`fulfillment` 也已完成包收口；其中 `campaign` 继续沿用内聚包级 `record` 的策略，`inventory`、`fulfillment` 直接复用现有 `dto` 目录。
- 运营治理相关的 `exceptioncenter`、`rule`、`servicecase` 也已完成包收口；其中 `rule` 采用内聚包级 `record` 的方式，`exceptioncenter`、`servicecase` 直接复用现有 `dto` 目录。
- 商品供应链与平台支持相关的 `product`、`supplier`、`support` 也已完成包收口，当前统一复用现有 `dto` 目录对齐标准骨架。
- 订单与治理协同相关的 `order`、`notification`、`approval` 也已完成包收口；其中 `notification`、`approval` 通过把原根包级请求 `record` 内聚为 `application` 层兼容服务的嵌套 `public record` 来完成迁移。
- 智能与直播相关的 `qa`、`live` 也已完成包收口；两者共享的请求/视图对象统一内聚到兼容层 `*Service`，避免在本轮迁移中新增 DTO 文件。
- `system` 模块的 `TenantSystemController` 也已迁入 `system/controller`，当前业务入口类已基本按文档收口到 `controller` / `application` 结构。

原因：
- `auth`、`tenant`、`organization` 是所有业务入口
- `saas` 与 `admin` 是租户和平台边界基础
- `order` 可作为第一批验证完整业务模块

## 13. 开发顺序建议
1. 先建公共支撑层：`tenant`、`security`、`audit`、`trace`
2. 再建平台底座模块：`auth`、`tenant`、`organization`、`saas`、`admin`
3. 再建主链路业务模块：`store`、`product`、`inventory`、`order`、`fulfillment`
4. 然后建智能与增长模块：`qa`、`live`、`campaign`、`member`
5. 最后建开放生态与指标模块：`openplatform`、`metrics`

## 14. 禁止事项
- 禁止把所有接口都写进一个 Controller
- 禁止用一个 `service` 包塞入所有模块逻辑
- 禁止跨模块直接查库绕过领域边界
- 禁止缓存 Key 不带租户维度
- 禁止平台支持入口绕过支持会话（support session）
