## 1. 文档目的

定义项目发布门禁、CI/CD 基线、发布步骤、回滚触发条件与回滚动作顺序。

## 2. 发布前门禁

- JDK 21 与 Maven 3.9.x 环境确认完成
- `mvn test` 全量通过，基线结果为 `Tests run: 74, Failures: 0, Errors: 0, Skipped: 0`
- 数据库迁移脚本已审阅，当前基线为 `V001` 到 `V018`
- `postgres` / `tunnel-local` / `server-local` profile 至少完成一套联调验收
- 无阻断级缺陷，回滚方案准备完成

## 3. CI/CD 与发布流水线基线

1. 拉取待发布代码并锁定版本号。
2. 切换到 JDK 21，执行全量测试。
3. 构建应用包与镜像产物，产出版本清单。
4. 在目标环境执行数据库迁移。
5. 按环境加载对应 profile。
6. 先灰度发布，再执行冒烟验证。
7. 打开定时任务与全量流量。
8. 观察经营看板、通知投递、财务账单与异常中心至少 30 分钟。

## 4. 标准发布步骤

1. 冻结待发布版本。
2. 备份关键配置、数据库与 Redis 关键键空间。
3. 执行应用发布。
4. 执行数据库变更。
5. 执行健康检查与关键接口冒烟。
6. 验证核心主链路：
   - 租户登录与上下文
   - 店铺/商品/订单链路
   - 审批与通知
   - 会员/财务/看板
7. 打开外部流量或定时任务。

## 5. 回滚触发条件

- 主链路不可用
- 数据写入异常或迁移失败
- 大面积平台接口失败
- 通知任务、财务账单或经营看板出现持续错误
- 自动化任务异常放大且无法快速止血

## 6. 回滚策略

### 6.1 回滚顺序

1. 暂停高风险自动化任务与定时任务。
2. 切换人工兜底模式。
3. 回滚应用版本。
4. 回滚配置。
5. 对数据库执行回滚脚本或补偿脚本。
6. 恢复备份数据并重新验证关键接口。

### 6.2 数据回滚原则

- 不允许直接手工改生产数据替代正式补偿脚本。
- 结构变更优先使用反向迁移或受控补偿脚本。
- 账单、通知、审批等有审计要求的数据必须保留回滚记录。

## 7. 发布后检查

- 首页与健康检查接口可用
- 店铺授权、订单同步、履约任务正常
- 审批流转与通知投递正常
- 会员标签、人群导出、财务账单、看板接口正常
- 告警系统、巡检任务与日志采集正常

## 8. 发布记录要求

- 记录发布版本、发布时间、执行人、回滚点
- 记录迁移版本、目标环境与启用 profile
- 记录灰度时长、冒烟结果与异常处置
- 记录是否触发回滚以及最终结论
