# 研发协作与代码规范

## 1. 文档目的
统一研发协作方式、分支策略、提交要求和联调规范。

## 2. 分支建议
- main：稳定主分支
- develop：集成分支
- feature/*：功能分支
- fix/*：修复分支
- release/*：发布准备分支

## 3. 提交规范
- 提交信息简洁明确
- 一个提交尽量只做一类变更
- 重要变更要说明影响范围

## 4. 接口协作要求
- 接口文档先行
- Mock 数据提前提供
- 错误码统一
- 回调格式统一

## 5. 代码基本原则
- 业务逻辑与平台接入解耦
- 核心流程可追踪
- 避免魔法值
- 错误处理必须可定位

## 6. 联调原则
- 先前后端联调，再平台联调
- 先主链路联调，再边缘场景联调
- 所有联调问题必须形成问题清单
