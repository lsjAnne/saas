## 1. 文档定位

- 这份文档只回答三件事：现在做到哪一步、接下来先做什么、哪些事情受外部条件阻塞。

## 2. 当前真实基线

截至 **2026-07-17**，当前仓库的真实状态应理解为：

1. 阶段 `0-12` 的核心业务主链路已经形成可持续开发基线。
2. `REQ-P0-* / REQ-P1-* / REQ-P2-*` 的首轮页面与主要交互闭环已经落地，不再属于“大量缺页未开发”状态。
3. 后端工程边界已经切换为 `backend/`，前端工程为 `frontend/`，旧 `src/main/java/com/dianshang/...` 处于迁移删除态，不应再被当作当前真实代码基线。
4. 直播与开放平台这条本地可落地缺口已继续收口：直播承诺白名单、互动自动回复、文档口径控场接口、开放平台凭证治理与前端接线已补齐并完成定向验证。
5. 当前真正未完成的事项，已经不再主要是“补业务页面”，而是：
   - 本地仍可继续推进的治理收口。
   - 依赖真实外部资源的阶段 13 接线与验收。

一句话结论：

> 当前项目已经从“继续补主要业务功能”进入“治理收口 + 外部接线准备”的阶段。

## 3. 已完成范围

### 3.1 核心业务与前后端基线

以下能力已具备当前工程基线：

- SaaS 平台底座：租户、组织、权限、订阅、计费、审计、停复服。
- 业务主链路：商品、供应商、库存、补货、订单、履约、异常、售后、会员、营销、财务、经营分析。
- 控制台前端：`frontend/` 已覆盖主要运营、管理与治理页面，不再是占位空壳。
- 后端工程：真实代码树已切换为 `backend/src/main/java/backend` 与 `backend/src/test/java/backend`。

### 3.2 需求补完首轮闭环

按当前代码与已验证结果，以下需求线已完成首轮闭环：

- `REQ-P0-*`：异常中心、商品映射、内容素材中心、经营分析、登录与店铺接入、经营助手、组织与权限中心。
- `REQ-P1-*`：驾驶舱、开放平台中心、通知中心、租户中心、订阅与计费中心、平台管理经营视图。
- `REQ-P2-*`：客服商用闭环、经营问答、直播互动治理、商品图片生成视频并剪辑发布闭环。

### 3.3 最近已经收口的本地缺口

这一轮已经完成并验证的本地补完包括：

- 直播高级治理接口补齐：
  - `GET /api/live-sessions/{id}/risk-events`
  - `POST /api/live-sessions/{id}/enable-control-mode`
  - `POST /api/live-sessions/{id}/resume-system-mode`
  - `POST /api/live-sessions/{id}/interaction/transfer`
  - `POST /api/live-sessions/{id}/commitments/confirm`
  - `POST /api/live-sessions/{id}/commitments/reject`
  - `POST /api/live-plans/{id}/configure-commitment-whitelist`
  - `POST /api/live-sessions/{id}/interaction/reply`
- 开放平台前端治理补齐：
  - 应用凭证列表、刷新、吊销
  - Webhook Secret 轮换
  - 更多 scope 选项接线
- 直播页前端治理补齐：
  - 承诺白名单配置
  - 自动回复
  - 会话风险事件
  - 文档口径控场启用与恢复

## 4. 当前未完成事项分层

### 4.1 第一层：本地仍可继续推进的事项

这些事项不依赖新的外部系统资源，仍然适合继续在当前仓库推进：

1. `GOV-01` 已完成：开放平台已切到细粒度 `scope` 白名单。
2. `GOV-02` 已完成：跨租户对象访问已收口为统一的防枚举错误口径。
3. `GOV-03` 已完成：插件中心已补齐本地插件治理聚合与前端治理视图。
4. 工程与文档基线清理：
   - 持续把 `05 / 06 / 02` 口径与真实代码同步。
   - 在不回滚用户改动的前提下，逐步收敛迁移后的脏工作树认知。

### 4.2 第二层：阶段 13 外部依赖事项

这些事项仍然是**发布阻塞项**，但它们是否能完成取决于真实外部环境，而不是只靠本地改代码：

1. `T13-01` 外部 ERP / WMS / BI / 消息系统真实接线。
2. `T13-02` 观测平台真实接线。
3. `T13-03` 发布与交付链路真实接线。
4. `T13-04` 标准 SaaS / 私有化双环境真实验收。

### 4.3 不应再被误判为主问题的事项

以下事项当前不应再被当作主线：

- “前端还没做完”。
- “核心业务模块还大量没开发”。
- “直播/开放平台还有明显本地缺页缺接口”。
- “仍停留在旧 `src/main/java/com/dianshang/...` 目录结构上继续开发”。

## 5. 当前开发顺序

基于现在的真实进度，后续开发顺序应调整为：

1. 先继续做 **本地可控的治理收口**：
   - `GOV-01` 更细粒度 scope：已完成
   - `GOV-02` 防串租户校验：已完成
   - `GOV-03` 插件中心深化：已完成
2. 每完成一批治理改动，执行当前高价值定向验证，确保 `backend/ + frontend/` 基线继续稳定。
3. 本地治理收口完成后，再按真实外部条件推进阶段 13：
   - 先 `APP_EXTERNAL_*`
   - 再 `APP_OBSERVABILITY_*`
   - 再 `APP_DELIVERY_*`
   - 最后做双环境正式验收

- 它们不能替代阶段 13 真实外部接线、真实观测平台接线和真实发布链路验收。
