## 1. 文档目的
定义系统测试范围、验收项、上线门槛、试运行规则、实施交底要求与缺陷分级标准。

## 1.1 自动化测试目标
- 核心主链路必须纳入自动化回归，避免功能迭代破坏经营闭环
- 高风险模块必须具备可重复执行的自动化验证，减少人工漏测
- 外部平台回调、定时任务、规则触发和直播异常场景必须可模拟
- 自动化测试结果必须作为上线门槛的一部分
- 直播高级治理必须以“设计文档 + 状态机 + 接口 + 测试矩阵 + Mock 联调 + 验收结论”六层闭环作为放行前提

- 商品映射与 SKU 校验
- 库存快照、补货建议与补货审批
- 订单同步
- 履约任务执行
- 物流回传
- 异常识别与处理
- 客户服务辅助
- 直播运营计划与脚本
- 直播高互动控场、复杂场景切换、人工接管与高风险承诺治理
- 客服售后记录
- 营销活动与优惠券
- 会员标签与 CRM 分层
- 财务账单与结算
- 审批流与消息通知

## 3. 功能验收项
### 3.1 接入与组织能力
- 能登录
- 能创建组织
- 能邀请成员并分配角色
- 能发起店铺授权
- 能看到授权状态
- 能保存基础参数

### 3.2 商品与供应链主链路
- 能采集候选商品
- 能设置供应商
- 能生成商品草稿
- 能建立货源映射
- 能进入待发布或发布状态

### 3.3 库存与补货主链路
- 能生成库存快照
- 能识别低库存商品
- 能创建补货任务
- 能提交补货审批
- 能回写处理结果

### 3.4 订单履约主链路
- 能同步订单
- 能生成履约任务
- 能执行代发
- 能回传物流
- 能追踪状态

### 3.5 异常主链路
- 能识别异常
- 能入异常中心
- 能给建议动作
- 能执行处理结果回写

### 3.6 客户服务辅助
- 能创建会话
- 能命中 FAQ 或知识库
- 能生成自动回复或建议回复
- 高风险问题可转人工

### 3.7 直播运营
- 能创建直播计划
- 能生成直播脚本
- 能启动、暂停和停止直播会话
- 直播异常可识别并提醒
- 同一直播账号重复开播时能正确拦截
- 同一店铺绑定多个直播账号时能支持多场并行直播
- 租户直播并发超过套餐限制时能正确拦截或进入排队
- 高互动评论能完成自动回复、转人工和强控场模式切换
- 场景切换失败后能回退或转人工接管
- 高风险承诺能执行白名单放行、人工确认、禁止承诺拦截三类处理
- 人工接管后会话状态、审计日志、履约跟踪和恢复系统直播动作正确

### 3.8 营销与会员
- 能创建营销活动
- 能进行活动审批与发布
- 能创建会员标签
- 能按标签筛选会员
- 能查看活动效果

### 3.9 财务与协作
- 能生成账单
- 能识别对账异常
- 能完成结算记录归档
- 能生成审批单并流转
- 能发送业务通知

### 3.10 开放平台
- 能创建应用
- 能下发凭证
- 能创建回调订阅（Webhook）
- 能记录 API 调用日志
- 权限不足时能正确拦截
- 外部 ERP 读取接口必须校验 `finance.read` scope，缺少 scope 时拒绝访问并记录调用日志

### 3.11 SaaS订阅与租户管理
- 能注册租户
- 能开通试用
- 能选择正式套餐
- 能续费、升级和降级
- 到期后能按规则限制或停服
- 配额超限时能正确拦截

### 3.12 商用安全与合规专项
- 认证链路必须使用真实 Bearer token，不能依赖演示账号或 legacy headers
- 生产配置不得依赖默认弱密钥，必须可通过环境变量完成替换与校验
- 租户级 RBAC 必须覆盖审计导出、生命周期治理、协议查询与协议确认等高风险能力
- 数据导出必须按租户边界返回，下载、清理计划、清理执行必须保留审计痕迹
- 退租清理必须先有影响清单，再执行定向删除，且不能误删账单、审计、合规留痕
- 开放平台应用凭据、Webhook 签名、时间窗、防重放、密钥轮换必须全部可验证
- 外部开放接口的 scope 授权必须同时覆盖“通过样例 + 拒绝样例”，不能只验证凭据有效
- 订阅到期自动化巡检必须能区分自动续费与自动停服，并留下账单或停服证据
- 隐私政策、用户协议查询与确认必须能查询版本、操作人和确认时间
- 平台支持或安全角色调取租户审计证据时，必须具备审批或受控访问前提

## 4. 非功能验收项
- 自动化失败不阻断整体链路
- 重试次数可控
- 高风险动作能拦截
- 高风险问答能拦截
- 高风险直播内容能拦截
- 评论洪峰、重复回调、乱序回调、延迟回调场景下直播治理逻辑稳定
- 审计日志完整
- 核心接口调用可追踪
- 多组织数据隔离正确
- 回调订阅（Webhook）幂等
- Webhook 密钥轮换后旧签名必须立即失效
- 插件与开放接口权限边界正确
- 订阅状态和能力开关一致
- 配额控制和套餐限制一致
- 生产环境弱密钥检查必须阻断上线
- 直播指标、报表和前台运行状态口径一致

## 5. 自动化测试范围
### 5.1 单元测试
- 规则计算、状态流转、风控判定、配额校验、价格库存校验必须有单元测试

### 5.2 接口自动化测试
- 登录鉴权、商品主链路、订单履约、问答、直播、订阅与权限接口必须覆盖
- 回调签名校验、幂等、重试和错误码返回必须覆盖

### 5.3 端到端自动化测试
- 新租户开通到店铺接入的首用链路
- 选品到商品发布链路
- 订单同步到履约回传链路
- 买家提问到自动回复或转人工链路
- 直播计划创建到开播、暂停、结束与异常中断链路

### 5.4 仿真与回归测试
- 外部平台限流、失败、超时、重复回调场景
- 直播账号占用冲突、店铺多账号并行、租户并发超限场景
- 高风险问答、高风险直播脚本和高风险审批动作场景
- 定时任务、队列消费、通知失败重试场景
- 评论洪峰、强控场切换、场景切换失败回退、人工接管、承诺审批超时场景

### 5.5 自动化测试门禁
- 主链路自动化测试通过率必须达到 100%
- 非主链路自动化测试通过率不得低于 95%
- 新增核心模块必须同步补充自动化测试后方可提测
- 生产发布前必须完成至少 1 轮完整回归
- 直播专项 P0 用例必须 100% 通过，且至少完成 1 轮专项演练

## 6. 直播专项验收结论规则
### 6.1 阻断项
- 同账号重复开播未拦截
- 高风险承诺可绕过人工确认直接播报
- 场景切换失败后既未回退也未人工接管
- 人工接管触发后无接管记录、无状态切换或无审计日志
- 多租户直播评论、承诺审批、接管记录或直播指标串租户

说明：
- 以上任一项命中，直接判定验收不通过，不允许上线

### 6.2 重点通过项
- 强控场模式切换后，页面、接口、数据库、埋点口径一致
- 承诺审批通过后，`approvalId`、`commitmentAuditId`、履约跟踪要求关联正确
- 评论洪峰下自动回复、转人工、人工接单、人工回复链路完整
- 连续切换失败达到阈值后，必须触发人工接管建议或自动接管流程
- BI 指标中的接管率、承诺拦截率、场景切换成功率与测试抽样一致

### 6.3 验收通过条件
- 主链路全通过
- 直播专项 P0 用例全通过
- 无 P0 缺陷
- 无未收敛的 P1 缺陷
- Mock 联调、回调仿真、专项演练、BI 抽样核对全部完成
- 验收结论必须给出明确“允许上线 / 不允许上线”

## 7. 缺陷分级
- P0：阻断主链路，不能上线
- P1：关键能力异常，需优先修复
- P2：体验问题，可跟版本修复
- P3：低优先级问题

直播专项缺陷补充规则：
- `manual_takeover` 状态错误、承诺误放行、回退失败无兜底，默认至少按 P1
- 串租户、误播高风险承诺、接管失效、回调幂等失效，直接按 P0
- 指标延迟但不影响实时风控和主链路的，可评估为 P2，但必须列入观察项

## 8. 上线门槛
- 主链路全通过
- 无 P0 缺陷
- 无未收敛的 P1 缺陷
- 自动化规则可启停
- 风控拦截可生效
- 日志与告警正常
- 权限隔离与审批流验收通过
- 开放平台鉴权验收通过
- SaaS 订阅与停复服验收通过
- 商用安全与合规专项验收通过
- 自动化测试报告输出完整
- 直播并发与套餐配额回归通过
- 直播专项回调仿真通过
- 评论洪峰、场景切换失败、人工接管、高风险承诺审批四类演练通过
- 直播 BI 指标抽样核对通过

### 8.0 正式放行总则
- 放行不是“功能基本可用”判断，而是“范围、质量、风险、证据、责任人”五项同时闭环后的正式决策
- 未完成需求范围确认、未完成证据归档、未完成缺陷收敛、未完成负责人签字的版本，一律不得进入放行
- 所有放行结论必须落到统一验收记录中，不能只以聊天、口头或临时截图代替
- 任何通过人工绕过权限、关闭校验、跳过演练、忽略告警获得的“通过结果”均视为无效验收
- 后续继续开发新能力前，必须先以本章节完成当前阶段放行检查，避免“边开发边默认上线”

### 8.1 商用安全与合规放行门槛
- `GET /api/me`、租户生命周期、审计导出、开放平台、合规确认链路全部基于 Bearer token 验证通过
- `AuthSecurityConfigVerifier` 对默认 token secret 与 bootstrap password 的告警已在上线检查中消除
- 数据导出、退租计划、退租执行、开放平台回调验证、订阅自动巡检均有自动化测试或演练记录
- 外部 ERP 读取接口的 `finance.read` scope 已有自动化通过样例与拒绝样例，且拒绝时能抽查 `rejected_scope` 调用日志
- Webhook 密钥轮换后，旧签名拒绝、新签名通过的专项回归结果明确
- 到期未自动续费租户会进入 `expired_suspended`，自动续费租户会生成 `auto_renew` 账单
- 协议确认表、导出任务表、清理任务表、开放平台调用日志表具备可抽查证据
- 审计抽样时至少能提供 `traceId`、操作人、时间、目标对象、结果状态五类字段

### 8.2 正式放行清单
- 范围确认：本次放行包含的模块、接口、数据对象、脚本、配置项、回滚范围必须有明确边界
- 功能验收：主链路、关键分支、失败分支、权限分支、恢复分支全部有通过记录
- 自动化验收：对应自动化测试必须执行完毕，并附测试时间、执行环境、总数、失败数、报告位置
- 配置验收：密钥、密码、租户配置、回调配置、套餐/配额配置必须完成生产口径校验
- 数据验收：关键表、关键状态流转、审计字段、导出文件、账单或清理记录必须可抽样复核
- 安全验收：鉴权、越权、幂等、防重放、弱配置、敏感操作审批与留痕必须通过
- 性能与容量验收：并发、配额、评论洪峰、回调乱序/重复、关键任务编排必须有专项结论
- 运维验收：日志、告警、巡检、失败重试、人工兜底、回滚预案必须准备完毕
- 交付验收：实施交底、观察期负责人、值班人、异常升级路径、复盘模板必须明确

### 8.3 放行证据要求
- 每项放行结论至少附 1 份可追溯证据，证据类型可为自动化报告、接口回包、数据库抽样、审计记录、演练记录
- 证据必须包含时间、环境、操作人或执行主体，不能只保留结果截图
- 涉及状态流转的能力，证据必须同时覆盖“触发前状态、执行动作、执行后状态”
- 涉及安全与合规的能力，证据必须覆盖“通过样例 + 拒绝样例”两类结果
- 涉及平台治理的能力，证据必须能抽查到 `traceId` 或等价关联标识

### 8.4 一票否决项
- 存在 P0 缺陷，直接不得放行
- 存在未收敛 P1 缺陷且会影响主链路、资金、权限、租户隔离、履约、审计或回调安全，直接不得放行
- 无法提供自动化结果或无法解释未自动化部分的人工验收证据，直接不得放行
- 默认弱密钥、默认密码、演示账号、legacy headers 依赖未消除，直接不得放行
- 无回滚预案、无异常联系人、无观察期负责人，直接不得放行
- 真实数据导出、退租清理、采购/订单/账单等关键状态无法抽样复核，直接不得放行

### 8.5 放行结论分级
- `允许放行`：全部门槛通过，无 P0、无未收敛 P1，证据齐全，观察期与责任人已明确
- `有条件放行`：仅允许存在不影响主链路和安全合规的 P2/P3，且已明确观察项、负责人、补救期限
- `拒绝放行`：任一一票否决项触发，或证据、责任、回滚、演练任一环节缺失
- `重新验收`：需求范围变化、关键配置变化、关键链路代码变化后，原放行结论自动失效

## 9. 试运行门槛
- 至少完成 1 场标准直播试运行
- 至少完成 1 场高互动评论洪峰试运行
- 至少完成 1 次场景切换失败回退演练
- 至少完成 1 次高风险承诺审批与履约跟踪演练
- 至少完成 1 次人工接管与恢复系统直播演练
- 试运行期间所有异常必须输出专项复盘结论

## 10. 实施交底要求
- 向测试、前后端、平台运营、直播运营、审批角色同步直播专项上线边界
- 明确哪些承诺允许自动表达，哪些必须人工确认，哪些绝对禁止
- 明确人工接管触发条件、接管角色、接管时限和恢复条件
- 明确场景切换失败后的回退顺序和升级联系人
- 明确 BI 指标观察口径、日报责任人和异常上报路径

## 11. 上线后观察期要求
- 观察期建议不少于 7 天
- 每日检查直播账号占用、并发排队、人工接管、承诺审批、场景切换失败统计
- 每日抽查至少 1 场直播的 `traceId`、风险事件、承诺审计和接管记录
- 观察期内若出现 P0 级直播专项问题，必须立即停止相应能力并回退到人工方案
- 观察期结束后输出专项观察报告，确认是否进入稳定运营

## 12. 验收结论模板
- 功能是否通过
- 风险是否可接受
- 是否允许上线
- 剩余问题清单

正式放行补充项：
- 放行结论是 `允许放行`、`有条件放行`、`拒绝放行` 还是 `重新验收`
- 本次放行范围、排除范围、回滚范围是否明确
- 自动化报告、人工演练记录、数据库抽样、审计证据是否全部归档
- 观察期负责人、值班联系人、异常升级路径、补救截止时间是否明确

商用安全与合规补充项：
- 生产密钥、默认密码、弱配置是否全部完成替换或阻断
- 租户导出、退租清理、开放平台回调、防重放、密钥轮换是否完成专项抽样
- 开放平台外部接口 scope 授权是否完成“通过 + 拒绝 + 日志留痕”三类抽样
- 自动续费与自动停服编排是否完成预演并留存账单/状态证据
- 合规确认、审计导出与平台支持受控访问边界是否明确

直播专项补充项：
- 直播专项 P0 用例是否全部通过
- 强控场、场景切换、人工接管、承诺审批是否完成演练
- 直播专项残余风险是否可控
- 观察期负责人和观察期策略是否明确
