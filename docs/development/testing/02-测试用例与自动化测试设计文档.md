## 1. 文档目的
本文档用于定义测试用例分层、自动化范围、测试数据设计和回归策略，确保平台在多租户和多系统协同场景下可持续验证。

## 2. 测试目标
- 保证主链路稳定
- 保证 OMS、SRM、ERP、CRM 主系统能力不回归
- 保证多租户、权限、配额和并发逻辑不回归
- 保证模型辅助能力可控、可降级、可留痕
- 保证直播高级治理能力在高互动、复杂切换和高风险承诺场景下可验证、可回退、可接管

## 4. 核心测试专题
### 4.1 SaaS 平台底座
- 多租户隔离
- 组织范围隔离
- 店铺数据可见性
- 支持会话时效与越权控制
- 日志导出脱敏校验

### 4.1.1 开放平台与外部集成专项

- Webhook 回调签名、时间窗、防重放、密钥轮换
- 外部 ERP 读取接口 `finance.read` scope 通过样例
- 外部 ERP 读取接口缺少 `finance.read` scope 的拒绝样例
- 拒绝访问时 `rejected_scope`、`rejected_secret`、`rejected_replay` 等调用日志留痕

### 4.2 OMS

### 4.6 直播高级治理

- 人工接管、恢复系统直播、接管留痕与履约跟踪

### 4.7 直播高级治理测试矩阵
| 测试编号 | 测试主题 | 优先级 | 测试层级 | 通过标准 |
| --- | --- | --- | --- | --- |
| LIVE-TC-001 | 直播计划创建到开播主链路 | P0 | API + E2E | 计划、脚本、排期、开播、结束全链路成功且状态留痕正确 |
| LIVE-TC-002 | 直播账号占用冲突拦截 | P0 | API + 集成 | 同账号重复开播被 `7101` 拦截，原会话不受影响 |
| LIVE-TC-003 | 租户并发配额超限与排队 | P0 | API + 集成 | 超限返回 `7102` 或进入 `queue_status=pending`，授权后可正常开播 |
| LIVE-TC-004 | 高互动评论自动回复与转人工 | P0 | API + 回调模拟 | 低风险问题自动回复，高风险问题转人工且不可误自动回复 |
| LIVE-TC-005 | 强控场模式切换 | P1 | API + E2E | `control_mode` 能在 `standard/enhanced/manual` 之间合法切换并生效 |
| LIVE-TC-006 | 场景切换成功与失败回退 | P0 | API + 回调模拟 | 切换失败返回 `7103` 后可正确回退，记录 `switch_status` 与 `rollback_status` |
| LIVE-TC-007 | 连续切换失败触发人工接管 | P0 | API + 集成 | 达到阈值后返回 `7105` 并生成 `takeover_status=active` 记录 |
| LIVE-TC-008 | 禁止承诺拦截 | P0 | API + 集成 | 命中禁止承诺返回 `7106`，不得生成可播报结果 |
| LIVE-TC-009 | 承诺人工确认与履约跟踪 | P0 | API + 集成 | 命中待确认承诺返回 `7107`，审批通过后生成履约跟踪记录 |
| LIVE-TC-010 | 人工接管与恢复系统直播 | P1 | API + E2E | 接管后会话进入 `manual_takeover`，恢复后状态与审计记录正确 |
| LIVE-TC-011 | 高风险直播异常中止 | P0 | API + 回调模拟 | 价格异常、库存不足、平台强制下播时能暂停、终止或降级 |
| LIVE-TC-012 | 直播指标与 BI 口径校验 | P1 | 数据校验 | 互动转化率、接管率、承诺拦截率、场景切换成功率统计正确 |

## 6. 自动化测试设计
### 6.1 自动化优先级
- P0 主链路全部自动化
- P1 高频功能优先自动化
- P2 页面体验类按成本选择自动化

### 6.2 自动化脚本分类
- API 自动化
- 页面 E2E 自动化
- 回调模拟自动化
- 数据校验自动化
- 模型回归自动化

### 6.3 直播专项自动化分层
| 自动化类型 | 覆盖内容 | 最低要求 |
| --- | --- | --- |
| API 自动化 | 计划、脚本、开播、暂停、结束、切换场景、控场模式、接管、承诺确认 | 覆盖全部 P0 直播接口 |
| 回调模拟自动化 | 开播成功、平台中断、库存变化、价格变化、评论洪峰、风险事件 | 支持幂等回放和重复回调验证 |
| 页面 E2E 自动化 | 直播运行页、互动区、场控区、人工接管区、风险承诺区 | 覆盖核心操作可视化行为和状态同步 |
| 数据校验自动化 | `live_session`、`live_risk_event`、`live_scene_switch_record`、`live_manual_takeover_record`、`live_commitment_audit` | 校验状态、时间、关联 ID 和租户归属一致 |
| BI 指标自动化 | 接管率、风险承诺拦截率、场景切换成功率、互动响应率 | 指标口径与设计文档一致 |

## 7. 多租户隔离必测场景
- A 租户管理员查询审计日志时，不能看到 B 租户任何记录
- A 租户管理员导出日志时，导出文件中不能包含 B 租户 `traceId`、店铺名、订单号
- 平台运营无支持会话时，不能进入租户业务详情页
- 支持会话过期后再次查询租户业务日志必须返回无权限
- 伪造 `tenantId`、`organizationId` 时，后端必须按登录态数据返回
- 同一个 `store_id` 在不同租户下不存在串查、串缓存、串导出
- 外部应用缺少 `finance.read` scope 时，不能读取 `/api/open/external/erp/*` 任何租户数据
- 外部应用即使凭据有效，也不能通过修改参数读取其他租户店铺、科目映射或集成基线

## 8. 回归策略
- 每次合并前执行冒烟
- 每日执行主链路回归
- 发布前执行完整回归
- 提示词或规则变更后执行专项回归
- 权限、日志、导出、缓存键或网关鉴权改动后执行多租户隔离专项回归

### 8.1 直播专项回归要求
- 涉及 `live_*` 表、直播接口、风控规则、审批规则、评论分类策略变更时，必须执行直播专项回归
- 涉及 `control_mode`、`scene_type`、`commitment_level`、`audit_status` 等枚举变更时，必须执行状态机和接口示例一致性复核
- 发布前直播专项回归必须至少覆盖 `LIVE-TC-001` 至 `LIVE-TC-009`
- 大促前必须增加评论洪峰、连续切换失败、人工接管协同三类压测与演练

## 9. 直播专项验收口径
### 9.1 阻断级验收项
- 同账号重复开播未被拦截，判定为 P0，禁止上线
- 高风险承诺可绕过人工确认直接播报，判定为 P0，禁止上线
- 场景切换失败后既未回退也未接管，判定为 P0，禁止上线
- 人工接管触发后状态、日志或接管记录缺失，判定为 P0，禁止上线
- 多租户直播数据串查、串写、串指标，判定为 P0，禁止上线

### 9.2 重点验收项
- 强控场模式切换后页面、接口、数据库状态保持一致
- 互动转人工后必须存在目标处理人、处理时长和处理结果
- 承诺审批通过后必须存在履约跟踪要求或明确的无需履约标记
- 直播 BI 指标与埋点口径一致，不允许前台和报表出现两套值

### 9.3 通过判定
- P0 用例全部通过
- P1 用例无未评估遗留缺陷
- 回调模拟、幂等、审计留痕、租户隔离四类基础能力必须全部通过
- 直播专项回归报告必须包含失败项、风险说明和结论，不允许只报“通过”

## 10. 缺陷流转要求
- P0 立即阻断发布
- P1 必须收敛后上线
- P2 评估后排期修复
- 缺陷必须关联系统域和复现步骤
- 直播专项缺陷必须额外关联测试编号、接口名、状态值、错误码和审计 `traceId`
- 涉及 `manual_takeover`、`commitment blocked`、`queue_status`、`rollback_failed` 的缺陷默认至少按 P1 评估

## 12. 结论
测试体系必须按 SaaS 平台底座、OMS、SRM/ERP、CRM、模型辅助能力、直播高级治理分域建立资产，才能支撑后续系统持续扩展而不失控。
