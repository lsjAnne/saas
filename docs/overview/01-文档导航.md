## 1. 这份导航解决什么问题

这份文档只做两件事：

- 告诉你每类信息应该看哪份文档。
- 统一当前项目文档的分层口径，避免把历史计划、开发流水和真实现状混在一起。

## 3. 当前统一口径

截至 `2026-07-04`，当前统一口径如下：

- 阶段 `0-12` 的核心业务主链路已基本落地，项目不再处于“从零搭系统”阶段。
- 当前真正主线是阶段 `13`，顺序仍是 `APP_EXTERNAL_* -> APP_OBSERVABILITY_* -> APP_DELIVERY_*`。
- 仓库内已经存在真实前端工程 `frontend/`，不是“只有后端、前端没做”。
- 需求与原型补完线已完成大部分页面与交互闭环，当前缺口主要不再是页面缺失，而是治理与真实接线缺口。
- 当前不能宣称“真实外部系统、真实观测平台、真实发布链路、双环境验收”已经完成，只能宣称本地工程闭环、门禁、摘要和定向验证已具备。
- 开发过程中的计划、停留点、任务顺序和 task 痕迹，应沉淀在 `05 / 06`，不应写进最终交付文档里替代开发交接。

## 4. 当前确认仍缺的功能与业务逻辑

以下项目应被视为当前正式缺口，而不是历史备注：

1. 外部系统真实接线未完成。
2. 观测平台真实接线未完成。
3. 发布与交付链路真实接线未完成。
4. 标准 SaaS / 私有化双环境真实验收未完成。

## 6. 维护规则

- `02` 只保留最终交付对比、最终放行边界和最终验收结论，不再作为开发中的交接文档。
- `05` 只保留当前开发阶段、完成版图、未完成项、开发顺序和阶段性计划。
- `06` 只保留当前待办、最近验证、真实停留点、继续开发顺序和开发过程 task 痕迹。
- `04` 仅作为历史估算与资源规划参考，不再作为今日进度判断依据。
- 任何“现在做到哪了”的回答，都必须优先交叉核对 `05 / 06` 与当前代码、测试、工作区状态。
