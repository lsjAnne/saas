## 1. 文档目的
统一系统的视觉风格、组件规则和交互原则，确保产品面向纯业务用户时保持清晰、稳定、易理解。

## 2. 设计目标
- 一眼看懂
- 风险突出
- 动作明确
- 信息不过载

## 3. 风格建议
- 主色以稳定、可信的蓝绿系为主
- 风险类状态使用橙红色
- 成功状态使用绿色
- 信息背景避免大面积高饱和色

## 4. 字体与层级
- 一级标题突出页面目标
- 指标数字优先展示
- 风险与待办使用较高对比度

## 5. 核心组件规范
### 指标卡片
- 只展示一个核心指标和一个辅助说明
- 支持状态颜色区分

### 风险提醒卡
- 包含风险标题、原因、建议动作
- 必须有明确按钮

### 会话卡片
- 显示客户问题摘要、风险标记、自动回复状态
- 显示是否已转人工

### 直播状态卡片
- 显示直播计划状态、当前讲解商品、异常提醒
- 提供启动、暂停、停止等明确操作

### 列表
- 保留搜索、筛选、状态标签
- 避免过多列

### 抽屉
- 用于展示详情与局部处理动作
- 避免复杂弹窗嵌套

## 6. 交互原则
- 系统建议必须带理由
- 高风险动作必须二次确认
- 自动完成的任务要有“已自动处理”标记
- 错误提示必须可读、可执行

## 7. 适配要求
- 桌面端优先
- 手机端至少支持查看首页、异常、订单和确认关键动作
