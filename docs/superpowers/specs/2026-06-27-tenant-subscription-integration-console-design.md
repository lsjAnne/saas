## 1. 文档说明

这份文档记录的是 `2026-06-27` 时点，为“租户订阅与外部集成交付范围控制台”准备的前端设计思路。

它主要保留了以下设计价值：

- 订阅与计费中心为什么要承载“外部软件可选配置”
- 为什么这个配置应被表达为“客户交付范围选择”，而不是简单技术开关
- 当时约定的页面分层、信息架构、状态边界和交互原则

## 2. 已过时的结论

以下表述现在已经过时，不能再直接使用：

1. “当前仓库尚无可用的真实前端工程”
2. “本次只规划、尚未落地登录页和后台壳子”
3. “订阅与计费中心仍处于纯设计阶段”

截至 `2026-07-04`，这些内容已被当前实现覆盖：

- 仓库内已有真实前端工程 `frontend/`
- 登录页、后台壳子、订阅与计费中心已落地
- 外部集成偏好已接入真实接口
- 当前重点已转向真实接线、真实观测、真实交付与治理收口

## 3. 仍然有效的设计原则

下面这些原则仍然有效：

1. 外部软件可选配置应该表达为客户所需交付范围，而不是技术开关列表。
2. 勾选状态与 readiness 状态必须分开，前端不能把“已选择”误显示成“已就绪”。
3. 页面容器不应直接散落复杂业务逻辑，请求应统一进入 `services` 层。
4. 跨页面共享状态进入 `stores`，局部交互状态留在 `features` 或组件内部。

## 4. 当前应如何使用这份文档

可以用它做：

- 回看订阅中心与外部集成偏好页的最初交互目标
- 对照当前实现是否仍遵守“交付范围选择器”的产品表达
- 复用其中仍然成立的状态边界和组件设计原则

不要再用它做：

- 判断当前项目是否还没有前端落地
- 判断当前订阅中心是否仍停留在原型阶段
- 判断当前项目真实进度
